## สัปดาห์ 22 — สถิติเชิงพรรณนาและการกระจายตัว

### เรียน (2 ชม.)

**ค่ากลาง 3 แบบ และเมื่อไหร่ใช้อันไหน**

| ค่า | ทนต่อค่าสุดโต่ง | ใช้เมื่อ |
|---|---|---|
| Mean | ไม่ทน | ข้อมูลกระจายสมมาตร |
| Median | ทน | ข้อมูลเบ้ หรือมี outlier |
| Mode | ทน | ข้อมูลหมวดหมู่ |

ผลตอบแทนคริปโตรายวันเบ้และมีหางอ้วน → **median น่าเชื่อกว่า mean** ในการอธิบาย
"วันทั่วไปเป็นยังไง" แต่ mean คือสิ่งที่กำหนดผลตอบแทนระยะยาว — ใช้คนละเรื่องกัน

**การกระจายตัว**
- **Variance / SD** — ค่าเฉลี่ยระยะห่างจากค่ากลาง
- **IQR** — ช่วงระหว่าง Q1 กับ Q3 ทนต่อ outlier
- **Skewness** — เบ้ซ้าย/ขวา
- **Kurtosis** — หางอ้วนแค่ไหน

```python
from scipy import stats
r = df.Close.pct_change().dropna()
print(f"mean {r.mean():.4%}  median {r.median():.4%}")
print(f"std {r.std():.4%}  skew {r.skew():.2f}  kurtosis {r.kurtosis():.2f}")
```

**หางอ้วนคือเรื่องเป็นเรื่องตาย**
ถ้าข้อมูลเป็น normal distribution เหตุการณ์ -5 SD ควรเกิดครั้งเดียวใน ~7 ล้านวัน
ในตลาดคริปโตมันเกิดหลายครั้งใน 8 ปี

ผลที่ตามมา: **สูตรความเสี่ยงทุกอันที่สมมติว่าผลตอบแทนเป็น normal จะประเมินความเสี่ยงต่ำเกินจริง**
รวมถึง Sharpe ratio, VaR แบบพารามิเตอร์, และ position sizing แบบ Kelly
ไม่ได้แปลว่าห้ามใช้ แปลว่าต้องรู้ว่ามันโกหกไปทางไหน

**ทดสอบความเป็น normal**
```python
stats.jarque_bera(r)        # p < 0.05 → ไม่ normal
stats.shapiro(r[:5000])
stats.probplot(r, dist="norm", plot=plt)    # Q-Q plot — ดูด้วยตาชัดที่สุด
```

**ทฤษฎีบทลิมิตกลาง (CLT)** — ค่าเฉลี่ยของกลุ่มตัวอย่างจะเข้าใกล้ normal
แม้ข้อมูลต้นทางไม่ normal นี่คือเหตุผลที่ t-test ยังใช้ได้กับผลตอบแทนคริปโต
(แต่ต้องมีตัวอย่างมากพอ และไม่ช่วยเรื่องหางอ้วนของ**ข้อมูลรายตัว**)

### ฝึก (3 ชม.)
1. คำนวณสถิติเชิงพรรณนาครบชุดของทั้ง 20 เหรียญ เรียงตาม kurtosis
2. วาด Q-Q plot ของ BTC เทียบกับ normal — เห็นหางอ้วนตรงไหน
3. เทียบ: ถ้าเป็น normal จริง วันที่ขาดทุนเกิน 10% ควรเกิดกี่ครั้ง เทียบกับที่เกิดจริง
4. คำนวณ VaR 95% สองแบบ: แบบ normal (`mean - 1.645*sd`) กับแบบ historical (percentile ที่ 5)
   — ต่างกันเท่าไหร่ อันไหนควรเชื่อ

## สัปดาห์ 23 — การทดสอบสมมติฐาน

### เรียน (2 ชม.)

**กรอบความคิด**
- `H₀` (null) — สมมติฐานว่า "ไม่มีอะไรพิเศษ" เช่น ผลตอบแทนวันจันทร์ = วันอื่น
- `H₁` (alternative) — สิ่งที่เราสงสัย
- **p-value** — ถ้า `H₀` จริง โอกาสที่จะเห็นข้อมูลสุดโต่งเท่านี้หรือมากกว่า มีเท่าไหร่
- `p < 0.05` → ปฏิเสธ `H₀`

🚨 **สิ่งที่ p-value ไม่ได้บอก** (คนเข้าใจผิดกันมากที่สุด)
- ❌ ไม่ได้บอกว่า "โอกาสที่ H₀ จริง คือ 5%"
- ❌ ไม่ได้บอกว่าผลลัพธ์**สำคัญ**หรือ**ใหญ่** — บอกแค่ว่ามันไม่น่าจะบังเอิญ
- ❌ `p = 0.049` กับ `p = 0.051` แทบไม่ต่างกันเลย เส้น 0.05 เป็นเรื่องสมมติล้วน ๆ

**Effect size สำคัญกว่า p-value**
ด้วยตัวอย่าง 3,000 วัน ความต่าง 0.01% ต่อวันก็ได้ `p < 0.05` ได้
แต่ 0.01% ต่อวันหักค่าธรรมเนียมแล้วไม่เหลืออะไร — **มีนัยสำคัญทางสถิติ ≠ มีค่าทางธุรกิจ**

รายงานเสมอ: ขนาดของผล + ช่วงความเชื่อมั่น ไม่ใช่แค่ p-value

**การทดสอบที่ต้องใช้เป็น**

| การทดสอบ | ใช้เมื่อ | โค้ด |
|---|---|---|
| One-sample t-test | ค่าเฉลี่ยต่างจากค่าหนึ่งไหม | `stats.ttest_1samp(r, 0)` |
| Two-sample t-test | สองกลุ่มต่างกันไหม | `stats.ttest_ind(a, b)` |
| Paired t-test | ก่อน-หลังในกลุ่มเดียว | `stats.ttest_rel(a, b)` |
| Mann-Whitney U | สองกลุ่ม ข้อมูลไม่ normal | `stats.mannwhitneyu(a, b)` |
| Chi-square | สองตัวแปรหมวดหมู่สัมพันธ์กันไหม | `stats.chi2_contingency(table)` |
| ANOVA | มากกว่าสองกลุ่ม | `stats.f_oneway(*groups)` |

**Multiple testing — กับดักที่ฆ่าระบบเทรดมานับไม่ถ้วน**

ถ้าทดสอบ 20 สมมติฐานที่ระดับ 0.05 โอกาสเจอ "ผลมีนัยสำคัญ" อย่างน้อย 1 อัน
ทั้งที่ไม่มีอะไรจริงเลย = `1 - 0.95²⁰ = 64%`

นี่คือสิ่งที่เกิดขึ้นทุกครั้งที่คนลองพารามิเตอร์ 50 ชุดแล้วเลือกอันที่ดีที่สุด
วิธีแก้:
- **Bonferroni** — ใช้เกณฑ์ `0.05 / จำนวนการทดสอบ` (เข้มงวดมาก)
- **FDR / Benjamini-Hochberg** — ผ่อนปรนกว่า เหมาะกับการทดสอบเยอะ ๆ
- **ที่ดีที่สุด: แยกข้อมูลออกมาชุดหนึ่งที่ไม่เคยแตะเลย** แล้วทดสอบครั้งเดียวตอนท้าย
  (Sprint 9 จะทำจริง)

**Bootstrap** — วิธีหาช่วงความเชื่อมั่นโดยไม่ต้องสมมติการกระจายตัว
```python
import numpy as np
means = [np.random.choice(r, len(r), replace=True).mean() for _ in range(10000)]
lo, hi = np.percentile(means, [2.5, 97.5])
print(f"ผลตอบแทนเฉลี่ยรายวัน 95% CI: [{lo:.4%}, {hi:.4%}]")
```
เหมาะกับข้อมูลการเงินมากเพราะไม่ต้องแกล้งว่าข้อมูล normal
ถ้าช่วงความเชื่อมั่นคร่อม 0 → ข้อมูลยังไม่พอจะบอกว่ามี edge

**Correlation ≠ Causation**
```python
stats.pearsonr(x, y)      # เชิงเส้น ไวต่อ outlier
stats.spearmanr(x, y)     # อันดับ ทนกว่า
```
⚠️ ในข้อมูลการเงิน correlation ของ**ราคา** แทบไม่มีความหมาย (spurious regression
เพราะทั้งคู่มีแนวโน้ม) ต้องคำนวณ correlation ของ**ผลตอบแทน**เสมอ

### ฝึก (3 ชม.)
1. ทดสอบว่าผลตอบแทนเฉลี่ยรายวันของ BTC ต่างจาก 0 อย่างมีนัยสำคัญไหม (t-test + bootstrap)
2. **ทดสอบข้อสงสัยจาก Sprint 1**: วันจันทร์ผลตอบแทนต่างจากวันอื่นจริงไหม
   - ทดสอบทั้ง 7 วัน แล้วปรับ p-value ด้วย Bonferroni
   - รายงาน effect size ไม่ใช่แค่ p
   - คำนวณว่าถ้าเทรดตามนี้ หักค่าธรรมเนียม 0.1% ต่อรอบแล้วเหลือเท่าไหร่
3. ทดสอบว่าวันที่ volume สูงผิดปกติ ตามมาด้วยผลตอบแทนที่ต่างจากวันปกติไหม
4. Chi-square: วันเขียวตามด้วยวันเขียวบ่อยกว่าที่ควรจะเป็นไหม (momentum จริงไหม)

## สัปดาห์ 24 — โปรเจกต์ส่ง

### โปรเจกต์ — Hypothesis Testing Report (5 ชม.)

สร้าง `bootcamp/sprint07/hypothesis.ipynb` + `findings.md`

**ทดสอบสมมติฐาน 5 ข้อ** เลือกจากรายการนี้หรือคิดเอง:

1. ผลตอบแทนวันจันทร์ต่างจากวันอื่น
2. เดือนมกราคมให้ผลตอบแทนดีกว่าเดือนอื่น
3. หลังวันที่ลงแรงเกิน 5% วันถัดไปมีแนวโน้มเด้ง (mean reversion)
4. วันที่ volume สูงกว่าค่าเฉลี่ย 20 วันเกิน 2 เท่า ตามด้วยความผันผวนสูงกว่าปกติ
5. เมื่อ RSI < 30 ผลตอบแทน 7 วันถัดไปดีกว่าค่าเฉลี่ย
6. altcoin ให้ผลตอบแทนดีกว่า BTC ในช่วงที่ BTC ขึ้น (altseason จริงไหม)

**แต่ละข้อต้องมีครบ 8 ส่วน:**

| ส่วน | ต้องมีอะไร |
|---|---|
| 1. สมมติฐาน | เขียน H₀ และ H₁ ให้ชัดเจนเป็นภาษาคน |
| 2. ข้อมูล | ใช้เหรียญไหน ช่วงไหน ตัดอะไรออก เพราะอะไร |
| 3. การทดสอบ | เลือกการทดสอบไหน **และทำไม** (normal ไหม กลุ่มอิสระไหม) |
| 4. ผลลัพธ์ | test statistic, p-value, **effect size**, **95% CI** |
| 5. ปรับ multiple testing | ทดสอบ 5 ข้อ → ปรับเกณฑ์ยังไง |
| 6. กราฟ | 1 กราฟที่แสดงผลให้เห็นด้วยตา |
| 7. เศรษฐศาสตร์ | ถ้าเทรดตามนี้ หักค่าธรรมเนียม 0.1%/รอบ แล้วเหลือ edge ไหม |
| 8. ข้อสรุป | ตอบตรง ๆ พร้อมระบุความมั่นใจ |

**ส่วนที่ 9 (บังคับ) — "ผมอาจจะหลอกตัวเอง"**
เขียนอย่างน้อย 3 ข้อว่าผลนี้อาจผิดได้ยังไง:
- ทดสอบกี่อย่างก่อนจะเจออันที่ significant (ตอบตามจริง)
- ข้อมูลชุดนี้เป็นตลาดขาขึ้นเป็นหลักไหม ถ้าใช่ ผลจะเปลี่ยนไหมในตลาดขาลง
- survivorship bias — เหรียญที่เจ๊งไปแล้วไม่อยู่ในข้อมูล
- ผลนี้จะยังจริงไหมถ้าเปลี่ยนช่วงเวลาทดสอบ (ลองจริง แล้วรายงาน)

**เกณฑ์ผ่าน:** ทุกข้อมี effect size และ CI ไม่ใช่แค่ p-value,
มีอย่างน้อย 1 ข้อที่คุณสรุปว่า "ไม่มีหลักฐานพอ" — ถ้าทั้ง 5 ข้อ significant หมด
ให้สงสัยตัวเองก่อน แล้วกลับไปตรวจ

> ข้อสุดท้ายไม่ได้กวน — ในการวิเคราะห์ตลาดจริง ผลส่วนใหญ่ที่ได้คือ "ไม่มีอะไร"
> การรายงานว่าไม่เจออะไรอย่างซื่อสัตย์ คือทักษะที่แยกนักวิเคราะห์ออกจากคนขายฝัน
