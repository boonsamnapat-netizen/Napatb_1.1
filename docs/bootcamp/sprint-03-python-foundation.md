## สัปดาห์ 8 — ตัวแปร ชนิดข้อมูล และเงื่อนไข

### เรียน (2 ชม.)

**ชนิดข้อมูลพื้นฐาน**
```python
price   = 68500.5          # float
symbol  = "BTCUSDT"        # str
is_long = True             # bool
count   = 42               # int
nothing = None             # NoneType — คนละอย่างกับ 0 และ ""
```

**กับดักเรื่อง float ที่ต้องรู้ตั้งแต่วันนี้**
```python
>>> 0.1 + 0.2 == 0.3
False                      # ไม่ใช่บั๊กของ Python — เป็นวิธีที่คอมพิวเตอร์เก็บทศนิยม
>>> 0.1 + 0.2
0.30000000000000004
```
ผลที่ตามมาในงานจริง: **ห้ามเทียบราคาด้วย `==`** ใช้ `abs(a - b) < 1e-9` แทน
โค้ดเช็ค "ราคาแตะ stop loss พอดี" ด้วย `==` จะไม่ทำงานและคุณจะหาสาเหตุไม่เจอเป็นวัน

**f-string** — วิธีจัดรูปแบบข้อความที่ควรใช้
```python
print(f"{symbol}: ${price:,.2f}")        # BTCUSDT: $68,500.50
print(f"กำไร {pnl:+.2%}")                # กำไร +3.42%
print(f"{name:<10}{value:>8.2f}")        # จัดคอลัมน์
```

**เงื่อนไข**
```python
if change > 5:
    label = "พุ่งแรง"
elif change > 0:
    label = "เขียว"
elif change == 0:
    label = "นิ่ง"
else:
    label = "แดง"
```

Python ใช้ **การเยื้อง (indentation)** แทนปีกกา — 4 ช่องว่างเสมอ ห้ามผสม tab กับ space

**Truthy / Falsy** — ค่าที่ Python ถือว่าเป็นเท็จ:
`False`, `0`, `0.0`, `""`, `[]`, `{}`, `None`
```python
if prices:          # อ่านว่า "ถ้า prices มีของอยู่"
    ...
```
⚠️ กับดัก: `if volume:` จะเป็นเท็จเมื่อ `volume = 0` ซึ่งอาจไม่ใช่สิ่งที่คุณตั้งใจ
ถ้าอยากเช็คว่า "มีค่าไหม" ให้ใช้ `if volume is not None:`

### ฝึก (3 ชม.)
1. รับราคาเข้า/ราคาออก คำนวณกำไร % แสดงผลด้วย f-string ให้สวย
2. เขียนฟังก์ชันจัดหมวดผลตอบแทนเป็น 5 ระดับด้วย if/elif
3. เขียนโปรแกรมถามราคา BTC จากผู้ใช้ ถ้ากรอกไม่ใช่ตัวเลขให้ถามใหม่ (ใช้ `try/except`)
4. พิสูจน์ปัญหา float ด้วยตัวเอง แล้วเขียนฟังก์ชัน `almost_equal(a, b)` มาแก้

## สัปดาห์ 9 — โครงสร้างข้อมูลและลูป

### เรียน (2 ชม.)

**4 โครงสร้างที่ต้องแยกออก**

| ชนิด | เขียนยังไง | แก้ได้ไหม | ใช้เมื่อ |
|---|---|---|---|
| `list` | `[1, 2, 3]` | ได้ | ลำดับของที่เปลี่ยนได้ |
| `tuple` | `(1, 2, 3)` | ไม่ได้ | ของที่ไม่ควรเปลี่ยน เช่นพิกัด |
| `dict` | `{"a": 1}` | ได้ | จับคู่ key → value |
| `set` | `{1, 2, 3}` | ได้ | ของไม่ซ้ำ, เช็คสมาชิกเร็ว |

```python
prices = [68500, 69200, 67800, 70100]
prices[0]      # 68500 — ตัวแรก
prices[-1]     # 70100 — ตัวสุดท้าย
prices[1:3]    # [69200, 67800] — ตัดตั้งแต่ 1 ถึงก่อน 3
prices[::-1]   # กลับลำดับ

coin = {"symbol": "BTCUSDT", "price": 68500, "trend": "up"}
coin["price"]              # 68500
coin.get("rsi", 50)        # 50 — ค่า default ถ้าไม่มี key นี้ (ปลอดภัยกว่า)
```

**ลูป**
```python
for p in prices:                          # วนค่า
for i, p in enumerate(prices):            # วนพร้อมลำดับ
for sym, price in coin_dict.items():      # วน dict
for a, b in zip(list1, list2):            # วนสองลิสต์พร้อมกัน
for i in range(1, len(prices)):           # วนด้วยเลข index
```

`zip` กับ `enumerate` จะใช้บ่อยมากตอนคำนวณค่าที่ต้องเทียบกับแถวก่อนหน้า
— ซึ่งก็คือ `LAG()` ของ SQL ที่เพิ่งเรียนไปนั่นเอง

**Comprehension** — วิธีเขียน list/dict แบบสั้น
```python
returns  = [(prices[i] - prices[i-1]) / prices[i-1] for i in range(1, len(prices))]
greens   = [r for r in returns if r > 0]
labels   = {s: "major" if s in ("BTCUSDT","ETHUSDT") else "alt" for s in symbols}
```

**ฟังก์ชันช่วยที่ควรรู้:** `len` `sum` `min` `max` `sorted` `any` `all` `abs` `round`
`sorted(data, key=lambda x: x["price"], reverse=True)`

3. เขียนฟังก์ชัน `max_drawdown(prices)` คืนค่าติดลบสูงสุดที่เคยเจอเป็น %
4. ใช้ dict นับว่าในหนึ่งปี มีวันเขียวกี่วัน วันแดงกี่วัน แยกตามเดือน

## สัปดาห์ 10 — ฟังก์ชันและการจัดการข้อผิดพลาด

### เรียน (2 ชม.)

```python
def position_size(balance: float, risk_pct: float,
                  entry: float, stop: float) -> float:
    """คำนวณขนาดโพสิชันจาก % ความเสี่ยงต่อไม้

    Args:
        balance:  เงินในพอร์ต (USD)
        risk_pct: ยอมเสียกี่ % ต่อไม้ เช่น 2.0
        entry:    ราคาเข้า
        stop:     ราคา stop loss

    Returns:
        จำนวนหน่วยที่ควรซื้อ

    Raises:
        ValueError: ถ้า entry เท่ากับ stop
    """
    if entry == stop:
        raise ValueError("entry กับ stop ต้องไม่เท่ากัน ไม่งั้นหารด้วยศูนย์")
    risk_amount = balance * risk_pct / 100
    risk_per_unit = abs(entry - stop)
    return risk_amount / risk_per_unit
```

องค์ประกอบที่ต้องมีทุกฟังก์ชันนับจากนี้: **type hint** + **docstring** + **ตรวจ input**
ไม่ใช่พิธีกรรม — มันคือสิ่งที่ทำให้คุณกลับมาอ่านโค้ดตัวเองอีก 3 เดือนแล้วยังเข้าใจ

**Default argument กับกับดักที่อันตรายที่สุดใน Python**
```python
def add_signal(sig, log=[]):    # ❌ ห้ามทำเด็ดขาด
    log.append(sig)
    return log
```
ลิสต์เปล่านั้นถูกสร้าง**ครั้งเดียว**ตอนนิยามฟังก์ชัน ทุกครั้งที่เรียกจะใช้ตัวเดิม
ข้อมูลจะสะสมข้ามการเรียก วิธีที่ถูก:
```python
def add_signal(sig, log=None):   # ✅
    if log is None:
        log = []
    log.append(sig)
    return log
```

**การจัดการข้อผิดพลาด**
```python
try:
    price = float(user_input)
except ValueError:
    print("กรอกตัวเลขด้วยครับ")
except (TypeError, KeyError) as e:
    print(f"ข้อมูลผิดรูปแบบ: {e}")
else:
    print("สำเร็จ")          # ทำเมื่อไม่มี error
finally:
    print("จบการทำงาน")      # ทำเสมอ
```

⚠️ **ห้ามเขียน `except:` เปล่า ๆ หรือ `except Exception: pass`**
มันจะกลืน error ทุกอย่างรวมถึงบั๊กของคุณเอง แล้วโปรแกรมจะเงียบ ๆ ให้ผลผิด
ซึ่งแย่กว่าโปรแกรมพัง

### ฝึก (3 ชม.)
1. เขียน `calculate_rr(entry, stop, target)` คืนอัตราส่วน risk/reward พร้อม validate
2. เขียน `atr(highs, lows, closes, period=14)` — สูตร ATR หาได้จาก `src/signal/indicators.py`
3. เขียนฟังก์ชันที่โยน `ValueError` เมื่อ input ผิด แล้วเขียนโค้ดเรียกที่จับ error นั้น
4. ลองสร้างบั๊ก mutable default argument ให้เกิดจริง ๆ แล้วอธิบายว่าเกิดอะไรขึ้น

## สัปดาห์ 11 — โปรเจกต์ส่ง

### โปรเจกต์ — Risk Calculator CLI (5 ชม.)

เขียนไฟล์ `bootcamp/sprint03/risk_calc.py` — โปรแกรมคำนวณความเสี่ยงที่ใช้ได้จริง
**ใช้แค่ Python มาตรฐาน ห้ามใช้ไลบรารีภายนอก**

**ความสามารถที่ต้องมี**

1. รับ input: เงินในพอร์ต, % เสี่ยงต่อไม้, ราคาเข้า, stop loss, target (ใส่หลายตัวได้)
2. คำนวณและแสดง:
   - ขนาดโพสิชัน (หน่วยและมูลค่า USD)
   - จำนวนเงินที่เสี่ยงจริง
   - R:R ของแต่ละ target
   - กำไร/ขาดทุนที่คาดหวังในหน่วย R
   - เตือนถ้า R:R ต่ำกว่า 1.5
3. ตรวจ input ทุกช่อง — entry = stop, ตัวเลขติดลบ, กรอกตัวหนังสือ ต้องไม่ทำโปรแกรมพัง

5. บันทึกทุกการคำนวณลงไฟล์ `trades.txt` พร้อมเวลา
6. โหมด `--summary` อ่าน `trades.txt` แล้วสรุปว่าคำนวณไปกี่ครั้ง เสี่ยงรวมเท่าไหร่

**ข้อกำหนดคุณภาพ**
- ทุกฟังก์ชันมี type hint + docstring
- ฟังก์ชันคำนวณต้องไม่มี `print` และไม่มี `input` — แยกตรรกะออกจากการรับส่งข้อมูล
  (เหตุผล: ฟังก์ชันบริสุทธิ์แบบนี้ทดสอบได้ ส่วนฟังก์ชันที่ `print` ทดสอบไม่ได้)
- ไฟล์ยาวไม่เกิน 200 บรรทัด — ถ้าเกิน แปลว่าฟังก์ชันใหญ่เกินไป
- มี `if __name__ == "__main__":` กั้นส่วนที่รันจริง

**ทดสอบด้วยเคสพวกนี้ให้ครบ**

| เคส | ผลที่ควรได้ |
