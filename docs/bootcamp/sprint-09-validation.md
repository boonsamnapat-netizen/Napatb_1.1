## สัปดาห์ 28 — Data Leakage

### เรียน (2 ชม.)

**Leakage คือ:** ข้อมูลที่โมเดลไม่ควรมี ณ เวลาที่ทำนาย หลุดเข้าไปในชุดฝึก

อาการ: ผลใน backtest ดีเกินจริงอย่างน่าสงสัย และผลจริงแย่กว่ามาก

**5 รูปแบบที่เจอบ่อยที่สุด**

**1. Look-ahead bias — ใช้ข้อมูลอนาคต**
```python
df["ma20"] = df.Close.rolling(20, center=True).mean()   # ❌ center=True ใช้อนาคต
df["signal"] = df.Close > df.Close.mean()               # ❌ mean ของทั้งชุดรวมอนาคต
df["norm"] = (df.x - df.x.mean()) / df.x.std()          # ❌ เหมือนกัน
```
เกณฑ์ตรวจ: **ทุกค่าใน feature ของวันที่ t ต้องคำนวณจากข้อมูลถึงวันที่ t เท่านั้น**

**2. Preprocessing leakage — normalize ก่อนแบ่งข้อมูล**
```python
X_scaled = StandardScaler().fit_transform(X)            # ❌ fit กับข้อมูลทั้งหมด
X_train, X_test = train_test_split(X_scaled)
```
ค่าเฉลี่ยและ SD มาจากข้อมูล test ด้วย → test ไม่ใช่ข้อมูลใหม่อีกต่อไป
**แก้ด้วย `Pipeline` เสมอ**

**3. Temporal leakage — แบ่งข้อมูลแบบสุ่มในอนุกรมเวลา**
```python
train_test_split(X, y, shuffle=True)    # ❌ ผิดสำหรับ time series เสมอ
```
นี่คือสิ่งที่เราจงใจทำผิดใน Sprint 8

**4. Survivorship bias — ข้อมูลมีแต่ผู้รอด**
20 เหรียญใน `data/real/crypto/` คือเหรียญที่ยังอยู่**ในปี 2026**
เหรียญที่เจ๊งไปในปี 2022 ไม่อยู่ในนั้น กลยุทธ์ที่ทดสอบกับข้อมูลชุดนี้จึงถูกทดสอบ
กับ "โลกที่ไม่มีเหรียญเจ๊ง" ซึ่งไม่ใช่โลกที่คุณเทรดจริง

นี่ไม่ใช่ปัญหาที่แก้ได้ด้วยโค้ด — ต้องรู้ตัวและหักส่วนลดจากผลลัพธ์ทุกครั้ง

**5. Overfitting ผ่านการปรับพารามิเตอร์ซ้ำ ๆ**
ลอง 200 ชุดพารามิเตอร์กับ test set เดียวกัน แล้วเลือกอันที่ดีที่สุด
= คุณ overfit กับ test set ไปแล้ว แม้จะไม่ได้ฝึกกับมัน
เชื่อมโยงตรงกับ multiple testing ใน Sprint 7

**Checklist ก่อนเชื่อผลลัพธ์ใด ๆ**
- [ ] ทุก feature ใช้ข้อมูลถึงเวลา t เท่านั้น (ไล่ทีละคอลัมน์)
- [ ] scaler/encoder fit กับ train เท่านั้น (ใช้ Pipeline)
- [ ] แบ่งข้อมูลตามเวลา ไม่ใช่สุ่ม
- [ ] test set ถูกใช้ **ครั้งเดียว** ตอนท้ายสุด
- [ ] ผลลัพธ์หักค่าธรรมเนียมและ slippage แล้ว
- [ ] เทียบกับ baseline (buy & hold, สุ่ม, ทายทางเดียวตลอด)

### ฝึก (3 ชม.)
1. กลับไปที่ notebook Sprint 8 ไล่ทุก feature หา leakage — เจอกี่จุด
2. สร้าง leakage โดยตั้งใจ: ใส่ `df.Close.shift(-1)` เป็น feature แล้วดู accuracy

   หรือ `rolling(center=True)`

## สัปดาห์ 29 — Walk-forward validation

### เรียน (2 ชม.)

**ทำไม k-fold ธรรมดาใช้ไม่ได้**
```
k-fold แบบสุ่ม:  [test][train][test][train][test]     ← ฝึกด้วยอนาคต ทดสอบกับอดีต
walk-forward:    [train][test]
                 [--train--][test]
                 [----train----][test]                 ← ฝึกด้วยอดีต ทดสอบอนาคต ✅
```

```python
from sklearn.model_selection import TimeSeriesSplit

tscv = TimeSeriesSplit(n_splits=5, gap=1)     # gap=1 กันข้อมูลติดกันรั่ว
for train_idx, test_idx in tscv.split(X):
    X_tr, X_te = X.iloc[train_idx], X.iloc[test_idx]
    y_tr, y_te = y.iloc[train_idx], y.iloc[test_idx]
    ...
```

**Expanding vs Rolling window**

| แบบ | ชุดฝึก | เหมาะเมื่อ |
|---|---|---|
| Expanding | โตขึ้นเรื่อย ๆ ตั้งแต่เริ่ม | ความสัมพันธ์คงที่ ยิ่งข้อมูลเยอะยิ่งดี |
| Rolling | หน้าต่างขนาดคงที่ ขยับไปเรื่อย | ตลาดเปลี่ยนพฤติกรรม ข้อมูลเก่าไม่เกี่ยว |

ตลาดคริปโตเปลี่ยนเยอะระหว่างปี 2018 กับ 2026 → ลองทั้งสองแบบแล้วเทียบ

**Purging และ Embargo**
ถ้า target ของคุณคือผลตอบแทน 5 วันข้างหน้า แถวสุดท้ายของ train set
จะมี target ที่ทับซ้อนกับ test set → ต้องตัดแถวคาบเกี่ยวออก (purge)
และเว้นช่องว่าง (embargo) เพิ่มอีกเล็กน้อย

**Combinatorial purged CV** — วิธีที่เข้มงวดที่สุด อ่านเพิ่มได้จากหนังสือ
*Advances in Financial Machine Learning* (López de Prado) แต่ยังไม่ต้องทำใน sprint นี้

**การแบ่งข้อมูล 3 ชุด — วิธีที่ถูกต้อง**
```
[--------- train 60% ---------][-- validation 20% --][-- test 20% --]
         ฝึกโมเดล                  เลือกพารามิเตอร์      แตะครั้งเดียว
```
**test set มีไว้ใช้ครั้งเดียวเท่านั้น** ถ้าดูผลแล้วกลับไปแก้โมเดล
test set ตัวนั้นตายแล้ว — มันกลายเป็น validation set ไปแล้ว

ในทางปฏิบัติ: ตัดข้อมูล 1–2 ปีหลังสุดออกไปเลย อย่าเปิดดู จนกว่าจะทำทุกอย่างเสร็จ

### ฝึก (3 ชม.)
1. เขียน walk-forward validation ด้วย `TimeSeriesSplit` กับโมเดล Sprint 8
2. เทียบ accuracy ที่ได้จาก random split กับ walk-forward — ต่างกันเท่าไหร่
3. ทำ expanding window เทียบ rolling window แล้วดูว่าอันไหนเสถียรกว่า
4. วาดกราฟ accuracy ของแต่ละ fold ตามเวลา — มันคงที่ไหม หรือแย่ลงเรื่อย ๆ

ข้อ 4 สำคัญ: ถ้า accuracy แย่ลงตามเวลา แปลว่า edge ที่เคยมีหายไปแล้ว
(alpha decay) ซึ่งเป็นเรื่องปกติมากในตลาดการเงิน
