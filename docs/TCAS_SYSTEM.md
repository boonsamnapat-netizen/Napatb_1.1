# TCAS70 — ระบบเตรียมสอบแพทย์ (กสพท)

ระบบช่วยวางแผนอ่านหนังสือ ฝึกทำข้อสอบ คำนวณคะแนน และจัดอันดับคณะ สำหรับการสอบ
เข้าคณะแพทย์ผ่าน **กสพท** ใน TCAS ปีการศึกษา 2570

แยกขาดจากระบบ crypto signal ในรีโปเดียวกัน — ใช้ร่วมกันแค่ธรรมเนียมการเขียนโค้ด
(config YAML + CLI + Telegram bot ตัวเดียวกันได้)

---

## ⚠️ อ่านก่อนใช้ — ข้อจำกัดของข้อมูล

แซนด์บ็อกซ์ที่สร้างระบบนี้ต่อเน็ตออกไม่ได้ **ตัวเลขต่อไปนี้จึงเป็นค่าประมาณ
ไม่ใช่ข้อมูลจากประกาศจริง** และถูกทำเครื่องหมาย `verified: false` ไว้ทั้งหมด:

| ข้อมูล | ไฟล์ | ต้องยืนยันกับ |
|---|---|---|
| วันสอบ TGAT/TPAT1/A-Level | `config/tcas_config.yaml` → `exams` | mytcas.com |
| วันสมัคร/ยื่นคะแนนแต่ละรอบ | `config/tcas_config.yaml` → `milestones` | mytcas.com |
| สัดส่วนคะแนน + เกณฑ์ขั้นต่ำ กสพท | `config/tcas_config.yaml` → `kaspot` | ประกาศ กสพท ปี 70 |
| คะแนนต่ำสุดย้อนหลังของแต่ละคณะ | `config/tcas_programs.yaml` → `cutoffs` | ประกาศผล กสพท ย้อนหลัง |

ทุกค่าปรับได้จาก YAML อย่างเดียว **ไม่ต้องแก้โค้ด** — เมื่อยืนยันแล้วให้ตั้ง
`verified: true` เพื่อให้เครื่องหมาย ⚠️ ในรายงานหายไป

ระบบนี้ช่วย *จัดระเบียบการเตรียมตัว* ไม่ได้รับประกันว่าจะสอบติด — ตัวเลขโอกาสติด
เป็นเพียงการเทียบคะแนนกับสถิติย้อนหลัง ไม่ได้คิดจำนวนผู้สมัครหรือความยากข้อสอบปีนั้น

## เริ่มใช้งาน

```bash
pip install pyyaml            # ต้องการแค่ตัวนี้ตัวเดียว

python tcas_cli.py today                  # ตารางวันนี้ + นับถอยหลัง
python tcas_cli.py plan --days 14         # ตารางล่วงหน้า 2 สัปดาห์
python tcas_cli.py quiz --subject bio -n 10
python tcas_cli.py progress               # อ่านไปถึงไหนแล้ว
```

จำลองวันที่อื่นได้ทุกคำสั่งด้วย `--date 2026-12-01` (หรือ env `TCAS_TODAY`)
มีประโยชน์ตอนอยากดูว่าตารางช่วงใกล้สอบหน้าตาเป็นยังไง

## คำสั่งทั้งหมด

| คำสั่ง | ทำอะไร |
|---|---|
| `today` | ตารางวันนี้ + นับถอยหลัง + หมุดหมายใกล้ถึง + คิวทบทวนค้าง |
| `plan --days N [--subject bio]` | ตารางอ่านหนังสือล่วงหน้า N วัน |
| `done <topic> [<topic>...]` | บันทึกว่าอ่านหัวข้อจบ → เข้าคิวทบทวนอัตโนมัติ |
| `topics [--subject bio]` | รายการหัวข้อทั้งหมด + สถานะ + ความแม่น |
| `bank` | สรุปคลังข้อสอบ และบอกว่าหัวข้อไหนยังไม่มีข้อสอบ |
| `quiz [--subject/--topic] [-n N] [--mode M]` | ทำชุดข้อสอบ |
| `score --set bio=72 [--target 74]` | กรอกคะแนน → คำนวณคะแนนรวม กสพท |
| `rank [--score 70.5] [--faculty แพทยศาสตร์]` | จัดอันดับคณะ + ประเมินโอกาส |

| `notify [--test]` | ส่งสรุปประจำวันเข้า Telegram |

## 0. เว็บแอป (วิธีที่ง่ายที่สุด)

```bash
python tcas_cli.py export     # ได้โฟลเดอร์ web/dist/ — ติดตั้งเป็นแอปได้
```

มี 5 หน้า: **วันนี้** (เช็คบล็อกที่ทำแล้ว) · **ตารางอ่าน** · **ตารางสอบ** ·
**ทำข้อสอบ** (ทำได้ในหน้าเลย ตอบผิดจะถูกดันมาถามซ้ำ) · **ความคืบหน้า**

### ตารางจัดใหม่เองทุกครั้งที่เปิด

หน้าเว็บ **ไม่ได้อ่านตารางที่ Python คำนวณไว้ตอน build** แต่จัดตารางใหม่เองในเบราว์เซอร์
ทุกครั้ง โดยเริ่มจาก *วันนี้* และ *ชั่วโมงที่ยังเหลือของแต่ละหัวข้อจริง ๆ*

ผลคือ **ข้ามไปกี่วันงานก็ไม่หาย** — จะถูกดันมาข้างหน้าให้เอง ไม่ต้องกดอะไรเพิ่ม
ความคืบหน้าผูกกับ *หัวข้อ* ไม่ใช่ *วันที่* (ของเดิมผูกกับวันที่ ทำให้ข้ามวันแล้วงานหลุดหาย)

ใช้สูตรจัดลำดับเดียวกับฝั่ง Python เป๊ะ:

```
คะแนน = น้ำหนักหัวข้อ × น้ำหนักวิชาใน กสพท × (1 − ความแม่น) × ความเร่งด่วน
```

บนหัวหน้า **วันนี้** มีแถบบอกว่ายังทันไหม โดยเทียบชั่วโมงที่ยังต้องอ่าน
กับชั่วโมงว่างที่เหลือจริงก่อนถึงวันสอบ — ตามทัน / ค่อนข้างตึง / ไม่ทันแล้ว

มี **streak** นับวันที่ทำต่อเนื่อง และแจ้งผลตอนติ๊กเสร็จ/ทำครบวัน

### ปุ่มเริ่มอ่าน + จับเวลา

หน้าแรกมีปุ่ม **เริ่มอ่าน** เป็นการกระทำหลัก กดแล้วจับเวลาเต็มจอตามความยาวของบล็อกนั้น
พัก/ไปต่อได้ ครบเวลาหรือกด *ทำเสร็จแล้ว* จะติ๊กบล็อกให้อัตโนมัติ

### หาอ่านจากไหน (ปุ่มหนังสือท้ายทุกบล็อก)

แตะปุ่มหนังสือข้างหัวข้อใดก็ได้ จะเปิดแผงบอกว่าไปเรียนหัวข้อนั้นได้ที่ไหน 3 ชั้น:

1. **ปุ่มค้นหา** — ยิงคำค้นจาก *ชื่อหัวข้อจริง* + คำต่อท้ายตามสนามสอบ
   (`TPAT1 กสพท ติว` หรือ `A-Level ติว สรุป`) ไปที่ YouTube / Google
   **กลไกนี้ไม่มีวันเสีย** เพราะไม่ได้พึ่งลิงก์ตายตัว
2. **ลิงก์ของฉัน** — เจอคลิปหรือสรุปดี ๆ วางลิงก์บันทึกไว้กับหัวข้อนั้นได้เลย
   ครั้งหน้าไม่ต้องหาใหม่ (เก็บในเครื่อง รวมอยู่ในไฟล์สำรองด้วย)
3. **แหล่งรวมของวิชานั้น** — จาก `config/tcas_resources.yaml`

⚠️ ลิงก์ใน `tcas_resources.yaml` มาจากผลค้นเว็บจริง แต่ **เปิดยืนยันทีละอันไม่ได้**
(เครื่องที่สร้างระบบถูกเว็บบล็อก HTTP 403) ทุกรายการจึงตั้ง `verified: false`
ลิงก์เสียเมื่อไรแก้ที่ไฟล์นี้ไฟล์เดียว ไม่ต้องแตะโค้ด

### ตั้งค่าในแอป (ปุ่มเฟืองมุมขวาบน)

แก้ **เวลาว่างรายวัน** · **วันหยุดเต็มวัน** · **ชื่อที่แสดง** ได้จากมือถือ
ค่าที่ตั้งเก็บใน localStorage และ**ทับ config ที่มากับตัวแอป** แผนคำนวณใหม่ทันที
ไม่ต้อง deploy — กด *คืนค่าเริ่มต้น* เพื่อกลับไปใช้ค่าใน YAML

### ติดตั้งเป็นแอปบนมือถือ (PWA)

push ขึ้น branch แล้ว workflow **`tcas_pages.yml`** จะ build และ deploy ขึ้น
GitHub Pages ให้อัตโนมัติ เปิดลิงก์บนมือถือแล้ว:

- **iOS (Safari)** — ปุ่มแชร์ → *Add to Home Screen*
- **Android (Chrome)** — เมนู ⋮ → *ติดตั้งแอป*

จะได้ไอคอนบนหน้าจอโฮม เปิดเต็มจอไม่มีแถบเบราว์เซอร์ และ **ใช้ได้ตอนไม่มีเน็ต**
(service worker แคชไว้ทั้งแอป)

ครั้งแรกต้องไปเปิด Pages ก่อน: **Settings → Pages → Source: GitHub Actions**
(ตัว workflow พยายามเปิดให้เองด้วย แต่บางทีสิทธิ์ไม่พอ)

> ⚠️ URL ของ Pages **เปิดสาธารณะ** ใครมีลิงก์ก็เปิดได้ ตัวแอปไม่มีข้อมูลส่วนตัว —
> ความคืบหน้าเก็บในเบราว์เซอร์เครื่องที่เปิดเท่านั้น ไม่เคยถูกอัปโหลด

### ทดสอบบนเครื่องตัวเองก่อน

```bash
python -m http.server -d web/dist 8000    # แล้วเปิด http://localhost:8000
```

ต้องเสิร์ฟผ่าน `http://` — เปิดไฟล์ตรง ๆ ด้วย `file://` service worker จะไม่ทำงาน
(หน้าเว็บยังใช้ได้ปกติ แค่ไม่มีโหมดออฟไลน์)

### อยากได้ไฟล์เดียวส่งต่อ

```bash
python tcas_cli.py export --single        # ได้ web/tcas_app.build.html
```

เปิดได้เลยโดยไม่ต้องมีเซิร์ฟเวอร์ แต่**ติดตั้งเป็นแอปไม่ได้** (PWA ต้องมี manifest
กับ service worker แยกไฟล์บน origin เดียวกัน)

### ที่เก็บข้อมูล

ความคืบหน้าเก็บใน localStorage ของเบราว์เซอร์เครื่องนั้น — **ไม่ได้ sync กับ
`data/tcas/progress.json` ที่ CLI ใช้** สองทางแยกกันเก็บ เลือกใช้ทางเดียวไปเลย

ย้ายเครื่อง/สำรองข้อมูล: หน้า **ความคืบหน้า** มีปุ่ม *สำรองข้อมูล* (ดาวน์โหลด JSON)
และ *กู้คืนจากไฟล์* — ไฟล์สำรองรุ่นเก่าก็กู้คืนได้ ระบบแปลงรูปแบบให้อัตโนมัติ

### แก้ดีไซน์หรือข้อมูล

โครงหน้าอยู่ที่ `web/tcas_app.html` (template, เป็น "เนื้อหาอย่างเดียว" ไม่มี
`<html>/<head>` เพื่อให้ publish เป็น Artifact ได้ด้วย) ข้อมูลถูกฝังตอน export
ตรงตัวคั่น `/*__TCAS_DATA__*/null` ส่วน `web/dist/` และ `.build.html` เป็นผลลัพธ์
ที่ generate ขึ้น จึงไม่ commit

รัน `export` ใหม่ทุกครั้งที่แก้ config หรือเพิ่มข้อสอบ (หรือแค่ push — workflow ทำให้)

## 1. แผนอ่านหนังสือ (`planner`)

แต่ละวันแบ่งเวลาเป็นสองส่วน:

1. **ทบทวน** (ค่าเริ่มต้น 25% ของเวลา) — หัวข้อที่ถึงคิวตาม spaced repetition
   ทำก่อนเสมอ เพราะอ่านแล้วลืมคือเสียเวลาเปล่า
2. **อ่านใหม่** — เลือกหัวข้อที่คุ้มที่สุดด้วยคะแนน

```
คะแนน = น้ำหนักหัวข้อ × น้ำหนักกลุ่มใน กสพท × (1 − ความแม่น) × ความเร่งด่วน
ความเร่งด่วน = ชั่วโมงที่ยังต้องอ่านของวิชานั้น ÷ ชั่วโมงว่างที่เหลือก่อนวันสอบวิชานั้น
```

ผลคือ **TPAT1 ถูกดันขึ้นมาก่อน A-Level โดยอัตโนมัติ** (เพราะสอบ ธ.ค. ไม่ใช่ มี.ค.)
ไม่ได้ฮาร์ดโค้ดลำดับไว้ — ถ้าแก้วันสอบใน config ลำดับจะขยับตามเอง

ตั้งเวลาว่างรายวันได้ที่ `study.hours_by_weekday` และใส่วันหยุดที่ `study.days_off`

`exams.*.counts_toward_kaspot` บอกว่าสนามนั้นมีน้ำหนักในคะแนน กสพท หรือไม่ —
ตัวนับถอยหลังหลักของแอปยึดเฉพาะสนามที่ `true` (TGAT ตั้ง `false` เพราะไม่ได้อยู่ในสูตร กสพท)

> ตารางที่ `plan` แสดงเป็นการ **จำลองล่วงหน้า** โดยสมมติว่าทบทวนแล้วจำได้ทุกครั้ง
> เวลาใช้จริงให้ยึด `today` ซึ่งอ่านสถานะจริงจาก progress

### บันทึกว่าอ่านจบแล้ว

```bash
python tcas_cli.py done bio_cell bio_photo
```

หัวข้อจะเข้าคิวทบทวนที่ 1 → 3 → 7 → 16 → 35 วัน (ปรับที่ `study.review_intervals_days`)

## 2. คลังข้อสอบ + quiz

ข้อสอบเก็บเป็น YAML หนึ่งไฟล์ต่อวิชาใน `data/tcas/questions/`
**เพิ่มข้อสอบได้โดยแก้ YAML อย่างเดียว**

```yaml
subject: bio                     # ต้องตรงกับรหัสวิชาใน syllabus.py
questions:
  - qid: bio_cell_001            # ห้ามซ้ำทั้งคลัง
    topic: bio_cell              # ต้องเป็นหัวข้อที่อยู่ในวิชานี้จริง
    stem: "คำถาม..."
    choices: ["ตัวเลือก ก", "ตัวเลือก ข", "ตัวเลือก ค", "ตัวเลือก ง"]
    answer: 2                    # index เริ่มที่ 0 → ข้อนี้เฉลย "ค"
    explanation: "ทำไมถึงตอบข้อนี้"
    difficulty: 2                # 1 ง่าย / 2 กลาง / 3 ยาก
```

`python tcas_cli.py bank` จะตรวจให้ทั้งหมด — qid ซ้ำ, เฉลยเกินจำนวนตัวเลือก,
หัวข้อผิดวิชา จะฟ้องทันทีพร้อมบอกว่าไฟล์ไหนข้อไหน

### โหมดเลือกข้อ (`--mode`)

| โหมด | เลือกข้อแบบไหน |
|---|---|
| `mixed` (ค่าเริ่มต้น) | ข้อที่ถึงคิวทบทวนก่อน แล้วเติมด้วยข้อใหม่ |
| `due` | เฉพาะข้อที่ถึงคิวทบทวนตาม SRS |
| `new` | เฉพาะข้อที่ยังไม่เคยทำ |
| `wrong` | เฉพาะข้อที่ตอบผิดครั้งล่าสุด |
| `all` | สุ่มจากทั้งคลัง |

`--auto` แสดงข้อพร้อมเฉลยโดยไม่ต้องตอบ และ**ไม่บันทึกสถิติ** — ใช้อ่านทบทวนหรือรันใน CI

### สิ่งที่เกิดขึ้นหลังตอบ

- ตอบถูก → ข้อนั้นถูกยืดคิวออกไป, ความแม่นของหัวข้อขยับขึ้น
- ตอบผิด → ข้อนั้นกลับมาถามพรุ่งนี้, ความแม่นลดลง, และถ้าหัวข้อนั้น "อ่านจบแล้ว"
  จะถูกดึงกลับเข้าคิวทบทวนทันที (ถือว่าลืม)

ความแม่นอัปเดตแบบ EWMA (น้ำหนักผลล่าสุด 30%) แล้วป้อนกลับเข้า planner ทำให้
**หัวข้อที่ทำข้อสอบผิดบ่อยจะถูกจัดเวลาให้มากขึ้นเอง**

## 3. คำนวณคะแนน กสพท

```
คะแนนรวม 100 = TPAT1 30%  +  A-Level 70%
ภายใน A-Level:  วิทย์ 40 · คณิต1 20 · อังกฤษ 20 · ไทย 10 · สังคม 10
(วิทย์ = เฉลี่ย ฟิสิกส์ เคมี ชีววิทยา น้ำหนักเท่ากัน)
```

```bash
python tcas_cli.py score --set tpat1=195 --set bio=72 --set chem=68 \
                         --set phys=61 --set math1=70 --set eng=78 \
                         --set thai=66 --set social=71 --target 74
```

TPAT1 กรอกจากคะแนนเต็ม 300, A-Level กรอกจากคะแนนเต็ม 100 (ระบบแปลงเป็น % ให้เอง)
คะแนนที่กรอกจะถูกจำไว้ กรอกเพิ่มทีละวิชาได้

- `--target` บอกว่ายังขาดอีกเท่าไร หรือต้องทำวิชาที่เหลือให้ได้เฉลี่ยกี่ %
- `--from-mastery` ประมาณคะแนนจากผล quiz แทน (หยาบมาก — ข้อสอบที่บ้านมักง่ายกว่าสนามจริง)

**เกณฑ์ขั้นต่ำ**: ต่ำกว่าเกณฑ์แม้วิชาเดียว = ตกทันที ไม่ว่าคะแนนรวมจะสูงแค่ไหน
ระบบจะขึ้น ❌ พร้อมบอกว่าวิชาไหนขาดเท่าไร

## รายชื่อคณะ (`config/tcas_programs.yaml`)

57 รายการ ครอบคลุมทั้ง 4 กลุ่มของ กสพท — แพทย์ 19 · ทันตแพทย์ 11 ·
เภสัช 18 · สัตวแพทย์ 9

**16 รายการแรกมี `cutoffs` ที่เป็นค่าประมาณ ส่วนอีก 41 รายการเว้นว่างไว้
โดยตั้งใจ** ไม่ใช่ลืม — เดาคะแนนต่ำสุดให้ครบ ๆ ไปก่อนอันตรายกว่าปล่อยว่าง
เพราะเป็นตัวเลขที่ผู้ใช้เอาไปตัดสินใจว่าจะยื่นที่ไหน

คณะที่ไม่มี cutoffs จะขึ้นว่า "ยังไม่มีคะแนน" ในตัวเลือก และผู้ใช้ยังใช้ฟีเจอร์
ห่างจากเป้าได้ด้วยการ**ใส่คะแนนเป้าหมายเอง**ในแอป (`S.settings.targetScore`)
ซึ่งทับค่าที่มากับตัวแอปเสมอ เพราะเขาไปเปิดประกาศจริงมา ส่วนของเรายังเป็นค่าประมาณ

### กรอกคะแนนต่ำสุดเข้าไป

ใช้คำสั่ง `cutoff` แทนการเปิดไฟล์แก้เอง — มันแก้เฉพาะสองบรรทัดของคณะนั้น
คอมเมนต์เตือนทั้งไฟล์ยังอยู่ครบ และอ่านไฟล์กลับมาตรวจให้ว่าค่าลงถูกที่จริง

```
python tcas_cli.py cutoff --list ทันตแพทยศาสตร์   # ดูรหัสคณะ + ที่ยังว่าง
python tcas_cli.py cutoff tu_dent 2568=70.4 2569=70.6
python tcas_cli.py export                          # ให้เว็บแอปเห็นค่าใหม่
```

ใส่หลายปีพร้อมกันได้ ปีที่มีอยู่แล้วจะถูกรวมไม่ใช่ทับทิ้ง และตั้ง `verified: true`
ให้อัตโนมัติ (ใช้ `--unverified` ถ้ายังไม่ได้เทียบกับประกาศ) ค่าที่นอกช่วง 0-100
หรือปีที่ไม่ใช่ พ.ศ. จะถูกปฏิเสธ เพราะกรอกผิดช่องคือความผิดพลาดที่เกิดบ่อยที่สุด

⚠️ **รายชื่อสถาบันที่เข้าร่วม กสพท เปลี่ยนได้ทุกปี** และบางแห่งเปิดเฉพาะบาง
หลักสูตร รายการนี้จึงเป็นจุดตั้งต้นให้ไล่ตรวจ ไม่ใช่ข้อมูลอ้างอิง

## หน้าคะแนน กสพท (ในเว็บแอป)

อยู่บนสุดของแท็บ **ความคืบหน้า** เพราะเป็นคำถามที่เด็กเปิดแอปมาเพื่อถาม

สูตรใน `web/tcas_app.html` (`scoreCard`, `requiredPercent`) **ลอกมาจาก
`src/tcas/scoring.py` ทีละบรรทัด** เพื่อให้ CLI กับแอปตอบตรงกัน ตรวจแล้วว่า
ให้ผลเท่ากันถึงทศนิยม — ถ้าแก้ฝั่งไหนต้องแก้อีกฝั่งด้วยเสมอ น้ำหนักและเกณฑ์
ขั้นต่ำอ่านจาก `DATA.weights` / `DATA.minimums` ที่ webexport ฝังมา ไม่ได้
ฮาร์ดโค้ดในหน้าเว็บ

**กติกาการแสดงผลที่ตั้งใจไว้ อย่าแก้โดยไม่ตั้งใจ**
- **ยังกรอกไม่ครบ** → ห้ามพาดหัวว่า "ยังขาดอีก N คะแนน" เพราะวิชาที่ยังไม่สอบ
  ถูกนับเป็น 0 ตัวเลขจะดูน่ากลัวเกินจริง ให้บอกแทนว่า *ที่เหลือต้องได้เฉลี่ยกี่ %*
  ซึ่งเป็นตัวเลขที่เอาไปวางแผนต่อได้
- **ตกเกณฑ์ขั้นต่ำ** → แถบต้องเป็นสีแดงและขึ้นเรื่องนี้ก่อนเสมอ ทับทุกสัญญาณอื่น
  เพราะตกเกณฑ์คือถูกคัดออกทันที ต่อให้คะแนนรวมสูงแค่ไหน
- คะแนนต่ำสุดของทุกคณะยัง `verified: false` — ทุกหน้าจอที่อ้างถึงต้องกำกับไว้

## ระบบดีไซน์ของหน้าเว็บ

แก้ทุกอย่างได้ที่ `web/tcas_app.html` ไฟล์เดียว (CSS อยู่บนสุด, JS อยู่ล่าง)

**ฟอนต์** — **IBM Plex Sans Thai** น้ำหนัก 400 กับ 600 ฝังอยู่ในไฟล์เป็น
base64 woff2 (18KB + 19KB) ไม่ได้โหลดจาก CDN แอปจึงใช้ได้แม้ออฟไลน์และ
ไม่มีทางตกไปฟอนต์อื่นเงียบ ๆ ที่ subset ไว้มี 227 ตัวอักษร คือภาษาไทย
ทั้งบล็อก + ละติน + เครื่องหมายที่แอปใช้จริง สัญลักษณ์คณิต/เคมี (Δ Σ ⇌ ₙ)
กับอิโมจิไม่ได้อยู่ใน subset จะตกไปฟอนต์ระบบตามปกติ

ถ้าจะเปลี่ยนฟอนต์ ต้อง subset ใหม่แล้วแปลงเป็น base64 ไม่ใช่แค่แก้ชื่อใน
`--sans` — ชื่อ `"Plex Thai"` ผูกกับ `@font-face` ที่ฝังไว้

*เดิมใช้ Sarabun ซึ่งเป็นฟอนต์ที่ ครม. กำหนดให้ใช้กับเอกสารราชการไทย
ปี 2553 หน้าตาแอปเลยอ่านเป็น "ใบงาน" ไม่ว่าจะทาสีอะไรลงไปก็ตาม*

**สี** — โทเคนอยู่ใน `:root` แล้วประกาศซ้ำอีกสองรอบ (`@media
prefers-color-scheme: dark` กับ `:root[data-theme=...]`) เพื่อให้ปุ่มสลับ
ธีมชนะค่าของระบบได้ทั้งสองทิศ พื้นเป็น**เทาอุ่น** สีหมึกเป็น**ม่วงเข้ม**
(`--ink`, ใช้กับแถบบน จอจับเวลา และไอคอนแอปใน `icons.py` — เปลี่ยนแล้ว
ต้องเปลี่ยน `THEME_COLOR` ใน `webexport.py` ตามด้วย)

สีประจำวิชา 8 สีอยู่ใน `[data-s="..."]` ตรวจด้วย `validate_palette.js` แล้ว
**ห้ามเอาสีวิชาไปทาตัวอักษรขนาดปกติ** — เขียวมะกอกกับเทอร์ควอยซ์ตัดกับพื้น
ไม่ถึง 4.5:1 ให้ใช้เป็นพื้น เส้นขอบ หรือเม็ดสีนำหน้าแทน (ดู `.srow-name`)

**มุมโค้ง** — `--r` 14px (การ์ด) · `--r-sm` 10px (ปุ่ม ช่องกรอก) ·
`--r-xs` 6px · `--pill` 99px (ชิป)

**ลูกเล่น** — ทุกอันเช็ค `prefers-reduced-motion` ก่อนเสมอ
- `runCounters()` — ตัวเลขวิ่งขึ้น จำค่าเดิมด้วย `data-key` เพื่อไม่ให้
  เด้งกลับศูนย์ทุกครั้งที่ render ใหม่
- `ringHTML()` — วงแหวนวาดตัวเองด้วย `stroke-dashoffset`
  (โหมดลดการเคลื่อนไหวจะกระโดดไป `--dash-to` ทันที ไม่ใช่ค้างว่าง)
- `confetti()` — เรียกจากที่เดียวคือตอนปิดงานครบทั้งวัน **ห้ามเรียกตอน
  ติ๊กทีละบล็อก** ไม่งั้นจะกลายเป็นเสียงรบกวนจนตอนที่ควรดีใจจริงไม่เหลือค่า
- `.blk.done.just` — เครื่องหมายถูกถูกวาดเฉพาะแถวที่เพิ่งกด
- `go()` — สลับแท็บผ่าน View Transitions ถ้าเบราว์เซอร์รองรับ

  container แล้วหัวสัปดาห์ที่เป็น `position: sticky` จะไปทับแถวของตัวเอง
- อะไรที่เป็น `<button>` แล้วตั้ง `border-top`/`border-bottom` อย่างเดียว
  ต้อง `border: 0` ก่อน ไม่งั้นเหลือ `2px outset` สีดำของเบราว์เซอร์สองข้าง
- อย่าผสม `ui-monospace` กับข้อความไทย — ตัวเลขกับตัวหนังสือจะกลายเป็น
  คนละฟอนต์ในบรรทัดเดียว ใช้ `font-variant-numeric: tabular-nums` แทน
