# TCAS70 — ระบบเตรียมสอบแพทย์ (กสพท)

ระบบช่วยวางแผนอ่านหนังสือ ฝึกทำข้อสอบ คำนวณคะแนน และจัดอันดับคณะ สำหรับการสอบ
เข้าคณะแพทย์ผ่าน **กสพท** ใน TCAS ปีการศึกษา 2570

แยกขาดจากระบบ crypto signal ในรีโปเดียวกัน — ใช้ร่วมกันแค่ธรรมเนียมการเขียนโค้ด
(config YAML + CLI + Telegram bot ตัวเดียวกันได้)

---

## ⚠️ อ่านก่อนใช้ — ข้อจำกัดของข้อมูล

แซนด์บ็อกซ์ที่สร้างระบบนี้ต่อเน็ตออกไม่ได้ ตัวเลขทุกตัวจึง**ตั้งต้น**เป็นค่าประมาณ
แล้วค่อยแทนที่ด้วยเอกสารจริงที่ผู้ใช้ถ่ายภาพมาให้ สถานะปัจจุบัน:

| ข้อมูล | ไฟล์ | สถานะ |
|---|---|---|
| วันสอบ TGAT/TPAT1/A-Level + ตารางสอบรายวิชา | `config/tcas_config.yaml` → `exams`, `subject_schedule` | ✅ ปฏิทินการสอบ TCAS70 (ทปอ.) |
| วันสมัคร/พิมพ์บัตร/ประกาศผล | `config/tcas_config.yaml` → `milestones` | ✅ 8 รายการจากปฏิทิน TCAS70 · ⚠️ 3 รายการยังคาดการณ์ |
| สัดส่วนคะแนน + เกณฑ์ขั้นต่ำ กสพท | `config/tcas_config.yaml` → `kaspot` | ⚠️ ประกาศ กสพท ฉบับที่ 1 **ปี 2569** (ปี 2570 ยังไม่ออก) |
| คะแนนต่ำสุดย้อนหลังของแต่ละคณะ | `config/tcas_programs.yaml` → `cutoffs` | ✅ 43 จาก 58 คณะ — สถิติ TCAS69 รอบ 3 |
| ลิงก์แหล่งเรียนฟรี | `config/tcas_resources.yaml` → `hubs` | ⚠️ 9 ลิงก์ยังไม่ได้เปิดตรวจ |

ทุกค่าปรับได้จาก YAML อย่างเดียว **ไม่ต้องแก้โค้ด** — เมื่อยืนยันแล้วให้ตั้ง
`verified: true` พร้อม `source` และ `source_year` เพื่อให้ตามรอยได้ว่ามาจากไหน

`source_year` ที่ไม่ตรงกับ `target_year` จะถูกรายงานเป็นระดับ **ควรตรวจ** ไม่ใช่
"ยืนยันแล้ว" — เพราะเกณฑ์ของปีที่แล้วเป็นของจริง แต่ก็ยังไม่ใช่ของปีที่กำลังจะสอบ

ระบบนี้ช่วย *จัดระเบียบการเตรียมตัว* ไม่ได้รับประกันว่าจะสอบติด — ตัวเลขโอกาสติด
เป็นเพียงการเทียบคะแนนกับสถิติย้อนหลัง ไม่ได้คิดจำนวนผู้สมัครหรือความยากข้อสอบปีนั้น

## เริ่มใช้งาน

```bash
pip install pyyaml            # ต้องการแค่ตัวนี้ตัวเดียว

python tcas_cli.py today                  # ตารางวันนี้ + นับถอยหลัง
python tcas_cli.py plan --days 14         # ตารางล่วงหน้า 2 สัปดาห์
python tcas_cli.py quiz --subject bio -n 10
python tcas_cli.py progress               # อ่านไปถึงไหนแล้ว
```

จำลองวันที่อื่นได้ทุกคำสั่งด้วย `--date 2026-12-01` (หรือ env `TCAS_TODAY`)
มีประโยชน์ตอนอยากดูว่าตารางช่วงใกล้สอบหน้าตาเป็นยังไง

## 0. เว็บแอป (วิธีที่ง่ายที่สุด)

```bash
python tcas_cli.py export     # ได้โฟลเดอร์ web/dist/ — ติดตั้งเป็นแอปได้
```

มี 5 หน้า: **วันนี้** (เช็คบล็อกที่ทำแล้ว) · **ตารางอ่าน** · **ตารางสอบ** ·
**ทำข้อสอบ** (ทำได้ในหน้าเลย ตอบผิดจะถูกดันมาถามซ้ำ) · **ความคืบหน้า**

### ตารางจัดใหม่เองทุกครั้งที่เปิด

หน้าเว็บ **ไม่ได้อ่านตารางที่ Python คำนวณไว้ตอน build** แต่จัดตารางใหม่เองในเบราว์เซอร์
ทุกครั้ง โดยเริ่มจาก *วันนี้* และ *ชั่วโมงที่ยังเหลือของแต่ละหัวข้อจริง ๆ*

ผลคือ **ข้ามไปกี่วันงานก็ไม่หาย** — จะถูกดันมาข้างหน้าให้เอง ไม่ต้องกดอะไรเพิ่ม
ความคืบหน้าผูกกับ *หัวข้อ* ไม่ใช่ *วันที่* (ของเดิมผูกกับวันที่ ทำให้ข้ามวันแล้วงานหลุดหาย)

ใช้สูตรจัดลำดับเดียวกับฝั่ง Python เป๊ะ:

```
คะแนน = น้ำหนักหัวข้อ × น้ำหนักวิชาใน กสพท × (1 − ความแม่น) × ความเร่งด่วน
```

บนหัวหน้า **วันนี้** มีแถบบอกว่ายังทันไหม โดยเทียบชั่วโมงที่ยังต้องอ่าน
กับชั่วโมงว่างที่เหลือจริงก่อนถึงวันสอบ — ตามทัน / ค่อนข้างตึง / ไม่ทันแล้ว

มี **streak** นับวันที่ทำต่อเนื่อง และแจ้งผลตอนติ๊กเสร็จ/ทำครบวัน

### ปุ่มเริ่มอ่าน + จับเวลา

หน้าแรกมีปุ่ม **เริ่มอ่าน** เป็นการกระทำหลัก กดแล้วจับเวลาเต็มจอตามความยาวของบล็อกนั้น
พัก/ไปต่อได้ ครบเวลาหรือกด *ทำเสร็จแล้ว* จะติ๊กบล็อกให้อัตโนมัติ

### หาอ่านจากไหน (ปุ่มหนังสือท้ายทุกบล็อก)

แตะปุ่มหนังสือข้างหัวข้อใดก็ได้ จะเปิดแผงบอกว่าไปเรียนหัวข้อนั้นได้ที่ไหน 3 ชั้น:

1. **ปุ่มค้นหา** — ยิงคำค้นจาก *ชื่อหัวข้อจริง* + คำต่อท้ายตามสนามสอบ
   (`TPAT1 กสพท ติว` หรือ `A-Level ติว สรุป`) ไปที่ YouTube / Google
   **กลไกนี้ไม่มีวันเสีย** เพราะไม่ได้พึ่งลิงก์ตายตัว
2. **ลิงก์ของฉัน** — เจอคลิปหรือสรุปดี ๆ วางลิงก์บันทึกไว้กับหัวข้อนั้นได้เลย
   ครั้งหน้าไม่ต้องหาใหม่ (เก็บในเครื่อง รวมอยู่ในไฟล์สำรองด้วย)
3. **แหล่งรวมของวิชานั้น** — จาก `config/tcas_resources.yaml`

⚠️ ลิงก์ใน `tcas_resources.yaml` มาจากผลค้นเว็บจริง แต่ **เปิดยืนยันทีละอันไม่ได้**
(เครื่องที่สร้างระบบถูกเว็บบล็อก HTTP 403) ทุกรายการจึงตั้ง `verified: false`
ลิงก์เสียเมื่อไรแก้ที่ไฟล์นี้ไฟล์เดียว ไม่ต้องแตะโค้ด

### ตั้งค่าในแอป (ปุ่มเฟืองมุมขวาบน)

แก้ **เวลาว่างรายวัน** · **วันหยุดเต็มวัน** · **ชื่อที่แสดง** ได้จากมือถือ
ค่าที่ตั้งเก็บใน localStorage และ**ทับ config ที่มากับตัวแอป** แผนคำนวณใหม่ทันที
ไม่ต้อง deploy — กด *คืนค่าเริ่มต้น* เพื่อกลับไปใช้ค่าใน YAML

ปุ่ม **ตอบคำถามเริ่มต้นใหม่** เปิดสามคำถามแรกขึ้นมาตอบใหม่ได้ (เดิม `seenIntro`
เป็นทางเดียว ตอบพลาดครั้งแรกแล้วแก้ไม่ได้เลยนอกจากล้างข้อมูลทั้งก้อน)
สไลเดอร์ "อ่านไปแล้วกี่ %" จะ**บวกเพิ่ม**จากของเดิม ไม่ใช่ตั้งทับ

### `ST` คำนวณใหม่ได้ — ห้ามใส่ `location.reload()` กลับเข้าไป

`ST` (เวลาว่าง + วันหยุดหลังผสมค่าที่ผู้ใช้ตั้ง) เดิมคำนวณครั้งเดียวตอนโหลด
ทุกที่ที่แก้ค่าจึงต้อง `location.reload()` ซึ่งพาผู้ใช้**เด้งกลับไปแท็บ "วันนี้"
ทุกครั้ง** — แก้เวลาว่างเจ็ดวันติดกันคือเด้งเจ็ดรอบ

ตอนนี้มี `buildST()` + `refreshST()` ที่แก้ค่าใน object เดิมแทนการสร้างก้อนใหม่
(ทั้งไฟล์อ้าง `ST` ตรง ๆ อยู่ ~20 จุด) ทุกจุดที่บันทึกค่าใช้
`Store.save(); refreshST(); render();` แทน reload

ในไฟล์ไม่เหลือ `location.reload()` ที่เป็นโค้ดจริงแม้แต่จุดเดียว (เหลือแต่ในคอมเมนต์) **ถ้าจะเพิ่มค่าที่
ต้องคำนวณตอนโหลด ให้เอาไปไว้ใน `buildST()` อย่าเพิ่ม reload กลับมา**

### กล่องโมดัลกับปุ่มออก

- แผงแหล่งอ่านเป็น `role="dialog" aria-modal="true"` กักโฟกัสไว้ข้างใน
  (`trapFocus()`) ล็อกสกรอลล์พื้นหลัง (`body.no-scroll`) ปิดด้วย Escape
  หรือแตะฉากดำ แล้ว**คืนโฟกัสกลับไปที่ปุ่มที่เปิดมัน** (`sheetOpener`)
  — ตอนวาดใหม่หลังเพิ่ม/ลบลิงก์ห้ามทับ `sheetOpener` (ดูตัวแปร `reopening`)
- ควิซมีปุ่ม **ออกจากชุดนี้** ตั้งแต่ยังไม่ตอบข้อแรก เดิมโผล่เฉพาะหลังตอบแล้ว
  คนที่เปิดผิดวิชาจึงต้องตอบมั่วหนึ่งข้อก่อน ซึ่งไปทำสถิติจุดอ่อนเสีย
  ถ้าตอบไปแล้วบางข้อจะถามยืนยันก่อน
- onboarding: **ข้ามทั้งหมด** ปิดจบทันทีโดยเก็บคำตอบที่ตอบไปแล้ว (เดิมทำงาน
  เหมือน "ถัดไป" เป๊ะ ๆ) และมี **ย้อนกลับ** ตั้งแต่ขั้นที่ 2

### ที่มาข้อมูลท้ายหน้าโผล่เฉพาะแท็บที่เกี่ยว

`FOOT_NOTES` + `renderFoot()` — แท็บทดสอบได้ที่มาของวันสอบ แท็บคะแนนได้ที่มา
ของคะแนนต่ำสุดกับสัดส่วน กสพท แท็บตั้งค่าได้วันที่สร้างข้อมูล ที่เหลือไม่มี
เดิมพิมพ์ทั้งสี่ย่อหน้าไว้ท้ายทุกแท็บ คำเตือนที่สำคัญที่สุด ("นี่เป็นตัวเลขของ
ปีที่แล้ว") จึงกลายเป็นสิ่งที่ตาเลื่อนข้ามทุกครั้ง

### ติดตั้งเป็นแอปบนมือถือ (PWA)

push ขึ้น branch แล้ว workflow **`tcas_pages.yml`** จะ build และ deploy ขึ้น
GitHub Pages ให้อัตโนมัติ เปิดลิงก์บนมือถือแล้ว:

- **iOS (Safari)** — ปุ่มแชร์ → *Add to Home Screen*
- **Android (Chrome)** — เมนู ⋮ → *ติดตั้งแอป*

จะได้ไอคอนบนหน้าจอโฮม เปิดเต็มจอไม่มีแถบเบราว์เซอร์ และ **ใช้ได้ตอนไม่มีเน็ต**
(service worker แคชไว้ทั้งแอป)

ครั้งแรกต้องไปเปิด Pages ก่อน: **Settings → Pages → Source: GitHub Actions**
(ตัว workflow พยายามเปิดให้เองด้วย แต่บางทีสิทธิ์ไม่พอ)

> ⚠️ URL ของ Pages **เปิดสาธารณะ** ใครมีลิงก์ก็เปิดได้ ตัวแอปไม่มีข้อมูลส่วนตัว —
> ความคืบหน้าเก็บในเบราว์เซอร์เครื่องที่เปิดเท่านั้น ไม่เคยถูกอัปโหลด

### ทดสอบบนเครื่องตัวเองก่อน

```bash
python -m http.server -d web/dist 8000    # แล้วเปิด http://localhost:8000
```

ต้องเสิร์ฟผ่าน `http://` — เปิดไฟล์ตรง ๆ ด้วย `file://` service worker จะไม่ทำงาน
(หน้าเว็บยังใช้ได้ปกติ แค่ไม่มีโหมดออฟไลน์)

### อยากได้ไฟล์เดียวส่งต่อ

```bash
python tcas_cli.py export --single        # ได้ web/tcas_app.build.html
```

เปิดได้เลยโดยไม่ต้องมีเซิร์ฟเวอร์ แต่**ติดตั้งเป็นแอปไม่ได้** (PWA ต้องมี manifest
กับ service worker แยกไฟล์บน origin เดียวกัน)

### กับดักเรื่องข้อมูลหาย — แก้แล้ว อย่าเขียนกลับ

ห้าอย่างนี้เคยทำให้ผู้ใช้เสียความคืบหน้าจริง โดยที่หน้าจอบอกว่าทุกอย่างปกติ

| เคย | ตอนนี้ |
|---|---|
| `Store.save()` จับ error แล้วตั้ง `usable = false` เงียบตลอดเซสชัน — พื้นที่เต็มแล้วติ๊กงานได้ ตัวเลขขยับ streak เดิน แต่ไม่มีอะไรลงดิสก์ | `save()` คืน `true//false` · แยก `QuotaExceededError` ออกจาก "เขียนไม่ได้ถาวร" · ลองใหม่ทุกครั้ง · ยิง `Store.onFail` ขึ้นแถบแดง `#saveWarn` ค้างบนจอ |
| ย้ายข้อมูลรุ่นเก่าแล้ว `delete S.done` ทันที ทั้งที่ชั่วโมงถูกหาจาก `DATA.plan` ของ build ปัจจุบัน (เริ่มที่วันที่ export) จึงมักจับคู่ไม่ได้เลย | แปลงได้ 0 รายการ = ไม่แตะต้นฉบับ ไม่ตั้ง `migrated` · แปลงได้ = เก็บไว้ใน `S.doneLegacy` |
| ตัวกู้คืน copy ทีละคีย์แบบเขียนมือ ลืม `scores` → ย้ายเครื่องแล้วคะแนนสอบหายหมด | `STATE_SHAPE` เป็นแหล่งความจริงเดียว คู่กับ `backupPayload()` |
| กู้คืนไฟล์ของแอปอื่นได้ · `runs` เป็น object ทำให้ `.push` พังถาวร · ไม่มี `reader.onerror` | `sanitizeBackup()` ตรวจ `app` + ชนิดทุกฟิลด์ + กรอง `javascript:` ออกจากลิงก์ |
| เขียนทับ `S` ก่อนแล้วค่อยเซฟ เซฟไม่ผ่านก็ยัง alert "กู้คืนเรียบร้อย" | `Store.replaceAll()` เซฟก่อน สำเร็จค่อยประกาศ ไม่สำเร็จคืนของเดิมครบ |

**`TODAY` ต้องเป็น `let` ไม่ใช่ `const`** — PWA บนมือถือถูก resume จากหน่วยความจำ
ไม่ได้โหลดหน้าใหม่ ถ้าแช่ค่าไว้ คนที่เปิดแอปค้างข้ามคืนจะเห็นตารางเมื่อวาน และ
งานที่ติ๊กวันนี้จะถูกบันทึกลง `S.log[เมื่อวาน]` ทำให้ streak ขาด
`refreshToday()` ผูกกับ `visibilitychange` / `pageshow` / `focus` + ตรวจทุกนาที

**`Vault.requestPersist()` เรียกตอนบูต** ไม่ใช่ตอนเข้าหน้าตั้งค่า — iOS ลบข้อมูล
เว็บที่ไม่ได้ปักหมุดและไม่ได้เปิดเกิน 7 วัน คนที่ใช้แค่แท็บ "วันนี้" จึงไม่เคยได้ปักหมุด

### ที่เก็บข้อมูล

ความคืบหน้าเก็บใน localStorage ของเบราว์เซอร์เครื่องนั้น — **ไม่ได้ sync กับ
`data/tcas/progress.json` ที่ CLI ใช้** สองทางแยกกันเก็บ เลือกใช้ทางเดียวไปเลย

ย้ายเครื่อง/สำรองข้อมูล: หน้า **ความคืบหน้า** มีปุ่ม *สำรองข้อมูล* (ดาวน์โหลด JSON)
และ *กู้คืนจากไฟล์* — ไฟล์สำรองรุ่นเก่าก็กู้คืนได้ ระบบแปลงรูปแบบให้อัตโนมัติ

### แก้ดีไซน์หรือข้อมูล

โครงหน้าอยู่ที่ `web/tcas_app.html` (template, เป็น "เนื้อหาอย่างเดียว" ไม่มี
`<html>/<head>` เพื่อให้ publish เป็น Artifact ได้ด้วย) ข้อมูลถูกฝังตอน export
ตรงตัวคั่น `/*__TCAS_DATA__*/null` ส่วน `web/dist/` และ `.build.html` เป็นผลลัพธ์
ที่ generate ขึ้น จึงไม่ commit

รัน `export` ใหม่ทุกครั้งที่แก้ config หรือเพิ่มข้อสอบ (หรือแค่ push — workflow ทำให้)

## 1. แผนอ่านหนังสือ (`planner`)

แต่ละวันแบ่งเวลาเป็นสองส่วน:

1. **ทบทวน** (ค่าเริ่มต้น 25% ของเวลา) — หัวข้อที่ถึงคิวตาม spaced repetition
   ทำก่อนเสมอ เพราะอ่านแล้วลืมคือเสียเวลาเปล่า
2. **อ่านใหม่** — เลือกหัวข้อที่คุ้มที่สุดด้วยคะแนน

```
คะแนน = น้ำหนักหัวข้อ × น้ำหนักกลุ่มใน กสพท × (1 − ความแม่น) × ความเร่งด่วน
ความเร่งด่วน = ชั่วโมงที่ยังต้องอ่านของวิชานั้น ÷ ชั่วโมงว่างที่เหลือก่อนวันสอบวิชานั้น
```

ผลคือ **TPAT1 ถูกดันขึ้นมาก่อน A-Level โดยอัตโนมัติ** (เพราะสอบ ธ.ค. ไม่ใช่ มี.ค.)
ไม่ได้ฮาร์ดโค้ดลำดับไว้ — ถ้าแก้วันสอบใน config ลำดับจะขยับตามเอง

ตั้งเวลาว่างรายวันได้ที่ `study.hours_by_weekday` และใส่วันหยุดที่ `study.days_off`

`exams.*.counts_toward_kaspot` บอกว่าสนามนั้นมีน้ำหนักในคะแนน กสพท หรือไม่ —
ตัวนับถอยหลังหลักของแอปยึดเฉพาะสนามที่ `true` (TGAT ตั้ง `false` เพราะไม่ได้อยู่ในสูตร กสพท)

> ตารางที่ `plan` แสดงเป็นการ **จำลองล่วงหน้า** โดยสมมติว่าทบทวนแล้วจำได้ทุกครั้ง
> เวลาใช้จริงให้ยึด `today` ซึ่งอ่านสถานะจริงจาก progress

### บันทึกว่าอ่านจบแล้ว

```bash
python tcas_cli.py done bio_cell bio_photo
```

หัวข้อจะเข้าคิวทบทวนที่ 1 → 3 → 7 → 16 → 35 วัน (ปรับที่ `study.review_intervals_days`)

## 2. คลังข้อสอบ + quiz

ข้อสอบเก็บเป็น YAML หนึ่งไฟล์ต่อวิชาใน `data/tcas/questions/`
**เพิ่มข้อสอบได้โดยแก้ YAML อย่างเดียว**

```yaml
subject: bio                     # ต้องตรงกับรหัสวิชาใน syllabus.py
questions:
  - qid: bio_cell_001            # ห้ามซ้ำทั้งคลัง
    topic: bio_cell              # ต้องเป็นหัวข้อที่อยู่ในวิชานี้จริง
    stem: "คำถาม..."
    choices: ["ตัวเลือก ก", "ตัวเลือก ข", "ตัวเลือก ค", "ตัวเลือก ง"]
    answer: 2                    # index เริ่มที่ 0 → ข้อนี้เฉลย "ค"
    explanation: "ทำไมถึงตอบข้อนี้"
    difficulty: 2                # 1 ง่าย / 2 กลาง / 3 ยาก
```

`python tcas_cli.py bank` จะตรวจให้ทั้งหมด — qid ซ้ำ, เฉลยเกินจำนวนตัวเลือก,
หัวข้อผิดวิชา จะฟ้องทันทีพร้อมบอกว่าไฟล์ไหนข้อไหน

### โหมดเลือกข้อ (`--mode`)

| โหมด | เลือกข้อแบบไหน |
|---|---|
| `mixed` (ค่าเริ่มต้น) | ข้อที่ถึงคิวทบทวนก่อน แล้วเติมด้วยข้อใหม่ |
| `due` | เฉพาะข้อที่ถึงคิวทบทวนตาม SRS |
| `new` | เฉพาะข้อที่ยังไม่เคยทำ |
| `wrong` | เฉพาะข้อที่ตอบผิดครั้งล่าสุด |
| `all` | สุ่มจากทั้งคลัง |

`--auto` แสดงข้อพร้อมเฉลยโดยไม่ต้องตอบ และ**ไม่บันทึกสถิติ** — ใช้อ่านทบทวนหรือรันใน CI

### สิ่งที่เกิดขึ้นหลังตอบ

- ตอบถูก → ข้อนั้นถูกยืดคิวออกไป, ความแม่นของหัวข้อขยับขึ้น
- ตอบผิด → ข้อนั้นกลับมาถามพรุ่งนี้, ความแม่นลดลง, และถ้าหัวข้อนั้น "อ่านจบแล้ว"
  จะถูกดึงกลับเข้าคิวทบทวนทันที (ถือว่าลืม)

ความแม่นอัปเดตแบบ EWMA (น้ำหนักผลล่าสุด 30%) แล้วป้อนกลับเข้า planner ทำให้
**หัวข้อที่ทำข้อสอบผิดบ่อยจะถูกจัดเวลาให้มากขึ้นเอง**

## 3. คำนวณคะแนน กสพท

```
คะแนนรวม 100 = TPAT1 30%  +  A-Level 70%
ภายใน A-Level:  วิทย์ 40 · คณิต1 20 · อังกฤษ 20 · ไทย 10 · สังคม 10
(วิทย์ = เฉลี่ย ฟิสิกส์ เคมี ชีววิทยา น้ำหนักเท่ากัน)

=> น้ำหนักจริงเทียบ 100: TPAT1 30 · วิทย์ 28 · คณิต1 14 · อังกฤษ 14 · ไทย 7 · สังคม 7
```

ถอดจาก **ประกาศ กสพท ฉบับที่ 1 ปีการศึกษา 2569 ข้อ 4** (ประกาศ 2 ก.ย. 2568)

```bash
python tcas_cli.py score --set tpat1=195 --set bio=72 --set chem=68 \
                         --set phys=61 --set math1=70 --set eng=78 \
                         --set thai=66 --set social=71 --target 74
```

TPAT1 กรอกจากคะแนนเต็ม 300, A-Level กรอกจากคะแนนเต็ม 100 (ระบบแปลงเป็น % ให้เอง)
คะแนนที่กรอกจะถูกจำไว้ กรอกเพิ่มทีละวิชาได้

- `--target` บอกว่ายังขาดอีกเท่าไร หรือต้องทำวิชาที่เหลือให้ได้เฉลี่ยกี่ %
- `--from-mastery` ประมาณคะแนนจากผล quiz แทน (หยาบมาก — ข้อสอบที่บ้านมักง่ายกว่าสนามจริง)

**เกณฑ์ขั้นต่ำ**: ประกาศเขียนว่า A-Level ต้องได้ *ไม่น้อยกว่า 30% ของคะแนนเต็ม
**ในแต่ละวิชา*** — ตกวิชาเดียวคือคัดออกทันที ไม่ว่าคะแนนรวมจะสูงแค่ไหน

คำว่า **แต่ละวิชา** คือหัวใจ และเคยเป็นบั๊กของระบบนี้: ฟิสิกส์ 20 / เคมี 40 /
ชีวะ 40 เฉลี่ยกลุ่มวิทย์ได้ 33% ถ้าเช็คที่ระดับ*กลุ่ม*จะขึ้นว่าผ่าน ทั้งที่ความจริง
ตกเพราะฟิสิกส์ไม่ถึง 30 — `scoring.check_minimums()` จึงไล่เช็คทีละวิชาเสมอ

ประกาศ **ไม่ได้** กำหนดเกณฑ์ขั้นต่ำของ TPAT1 (ช่องเงื่อนไขระบุแค่ว่าใช้คะแนน
ของวันสอบวันนั้น) — `tpat1_pct` จึงเป็น `null` ไม่ใช่ 30

## 4. จัดอันดับคณะ

```bash
python tcas_cli.py rank --score 70.5
python tcas_cli.py rank --faculty ทันตแพทยศาสตร์ --limit 10
python tcas_cli.py rank --score 67.9 --university ธรรมศาสตร์
```

`--faculty` กับ `--university` เป็นตัวกรองคนละแกน ใส่พร้อมกันได้ ทั้งคู่เทียบแบบ
substring จึงพิมพ์ `ธรรมศาสตร์` แทน `ม.ธรรมศาสตร์` ได้

คาดคะแนนต่ำสุดปีเป้าหมาย = ค่าล่าสุด + แนวโน้มเฉลี่ยต่อปี แล้วแบ่งเป็นแถบ:

| แถบ | ห่างจากคะแนนต่ำสุดที่คาด |
|---|---|
| 🟢 ปลอดภัย | +3 ขึ้นไป |
| 🟡 ลุ้น | 0 ถึง +3 |
| 🟠 ท้าทาย | −3 ถึง 0 |
| 🔴 เกินเอื้อม | ต่ำกว่า −3 |

ระบบยังเสนอ **ลำดับสำหรับรอบ 3** ด้วย โดยวาง "ท้าทาย" ไว้บนสุดและ "ปลอดภัย" ปิดท้าย
เพราะ TCAS จัดที่นั่งตามลำดับที่เลือก — ใส่คณะที่อยากได้จริงไว้อันดับต้นเสมอ

เพิ่ม/แก้คณะได้ที่ `config/tcas_programs.yaml`

## 4.5 ตารางทดสอบ

อ่านอย่างเดียวไม่รู้ว่าจำได้จริงไหม `src/tcas/testplan.py` จึงแทรกการวัดผล 3 ระดับ
ที่ derive จากตารางอ่าน + วันสอบจริง:

| ระดับ | เมื่อไร | ทดสอบอะไร |
|---|---|---|
| รายสัปดาห์ | ทุกวันอาทิตย์ | เฉพาะหัวข้อที่เพิ่งอ่านในสัปดาห์นั้น |
| รายเดือน | สิ้นเดือน | ทุกวิชาที่อ่านสะสมมา ไม่ใช่แค่ของใหม่ |
| สอบเสมือนจริง | ก่อนสอบจริง 60/30/14/7 วัน | จับเวลาเต็มรูปแบบ |

สอบเสมือนจริงจะเลี่ยงไม่ไปลงชนวันสอบจริงสนามอื่นโดยอัตโนมัติ

**จำนวนข้อที่แสดง นับจากคลังข้อสอบจริงเสมอ** ไม่ใช่ค่าประมาณจากจำนวนหัวข้อ
ถ้าหัวข้อไหนยังไม่มีข้อสอบ จะขึ้นคำเตือนบอกให้ไปเพิ่มที่ `data/tcas/questions/`
แทนที่จะโชว์ตัวเลขที่ทำตามไม่ได้

```bash
python tcas_cli.py tests --kind mock
```

### ตารางสอบจริง ≠ ตารางทดสอบ

หัวแท็บ "ตารางสอบ" ในเว็บแอปมีการ์ด **ตารางสอบจริง** อยู่บนสุด สร้างจาก
`config/tcas_config.yaml` → `subject_schedule` ซึ่งถอดจากปฏิทินการสอบ TCAS70:

| วัน | วิชา |
|---|---|
| 13 ก.พ. 70 | TPAT1 วิชาเฉพาะ กสพท (08.30-12.30) |
| 13 มี.ค. 70 | ชีววิทยา · ฟิสิกส์ · ภาษาไทย · สังคมศึกษา |
| 14 มี.ค. 70 | คณิตศาสตร์ 1 · ภาษาอังกฤษ · เคมี |

ต้องแยกให้ขาดจากตารางทดสอบด้านล่าง — **วันสอบจริงเปลี่ยนไม่ได้ วันซ้อมเลื่อนได้**
ตารางรายวิชานี้ยังทำให้เส้นตายของ planner แม่นขึ้นด้วย: ชีวะ/ฟิสิกส์/ไทย/สังคม
ต้องพร้อมก่อนคณิต/อังกฤษ/เคมี หนึ่งวัน (`config.subject_schedule()` ชนะวันสอบรวม)

### กรอกคะแนนต่ำสุดเข้าไป

ใช้คำสั่ง `cutoff` แทนการเปิดไฟล์แก้เอง — มันแก้เฉพาะสองบรรทัดของคณะนั้น
คอมเมนต์เตือนทั้งไฟล์ยังอยู่ครบ และอ่านไฟล์กลับมาตรวจให้ว่าค่าลงถูกที่จริง

```
python tcas_cli.py cutoff --list ทันตแพทยศาสตร์   # ดูรหัสคณะ + ที่ยังว่าง
python tcas_cli.py cutoff tu_dent 2569=69.3856
python tcas_cli.py export                          # ให้เว็บแอปเห็นค่าใหม่
```

ใส่หลายปีพร้อมกันได้ ปีที่มีอยู่แล้วจะถูกรวมไม่ใช่ทับทิ้ง และตั้ง `verified: true`
ให้อัตโนมัติ (ใช้ `--unverified` ถ้ายังไม่ได้เทียบกับประกาศ) ค่าที่นอกช่วง 0-100
หรือปีที่ไม่ใช่ พ.ศ. จะถูกปฏิเสธ เพราะกรอกผิดช่องคือความผิดพลาดที่เกิดบ่อยที่สุด

## หน้าคะแนน กสพท (ในเว็บแอป)

อยู่บนสุดของแท็บ **ความคืบหน้า** เพราะเป็นคำถามที่เด็กเปิดแอปมาเพื่อถาม

สูตรใน `web/tcas_app.html` (`scoreCard`, `requiredPercent`) **ลอกมาจาก
`src/tcas/scoring.py` ทีละบรรทัด** เพื่อให้ CLI กับแอปตอบตรงกัน ตรวจแล้วว่า
ให้ผลเท่ากันถึงทศนิยม — ถ้าแก้ฝั่งไหนต้องแก้อีกฝั่งด้วยเสมอ น้ำหนักและเกณฑ์
ขั้นต่ำอ่านจาก `DATA.weights` / `DATA.minimums` ที่ webexport ฝังมา ไม่ได้
ฮาร์ดโค้ดในหน้าเว็บ

**กติกาการแสดงผลที่ตั้งใจไว้ อย่าแก้โดยไม่ตั้งใจ**
- **ยังกรอกไม่ครบ** → ห้ามพาดหัวว่า "ยังขาดอีก N คะแนน" เพราะวิชาที่ยังไม่สอบ
  ถูกนับเป็น 0 ตัวเลขจะดูน่ากลัวเกินจริง ให้บอกแทนว่า *ที่เหลือต้องได้เฉลี่ยกี่ %*
  ซึ่งเป็นตัวเลขที่เอาไปวางแผนต่อได้
- **ตกเกณฑ์ขั้นต่ำ** → แถบต้องเป็นสีแดงและขึ้นเรื่องนี้ก่อนเสมอ ทับทุกสัญญาณอื่น
  เพราะตกเกณฑ์คือถูกคัดออกทันที ต่อให้คะแนนรวมสูงแค่ไหน
- คะแนนต่ำสุดของทุกคณะยัง `verified: false` — ทุกหน้าจอที่อ้างถึงต้องกำกับไว้

## หน้า "มีโอกาสติดที่ไหนบ้าง" (ในเว็บแอป)

อยู่ถัดจากการ์ดคะแนนทันที เพราะเป็นคำถามถัดไปในหัวเสมอ — กรอกคะแนนเสร็จ
ไม่มีใครอยากรู้ว่าอ่านหนังสือไปกี่ % ก่อนจะรู้ว่าคะแนนนี้ติดที่ไหน
โค้ดอยู่ที่ `chancePanel()` / `progRow()` ใน `web/tcas_app.html`

**ตั้งใจไม่แสดงเป็น "โอกาสติด 78%"** เพราะมีสถิติอยู่ปีเดียว จะคำนวณความน่าจะเป็น
จากจุดข้อมูลจุดเดียวไม่ได้ ตัวเลขที่ออกมาจะเป็นของปลอมที่ดูน่าเชื่อ ซึ่งอันตราย
กว่าไม่บอกอะไรเลย สิ่งที่บอกได้จริงคือ *ห่างจากคนสุดท้ายที่ติดเมื่อปีที่แล้วกี่คะแนน*
ขอบเขตของแถบ (`BANDS`) ใช้ค่าเดียวกับ `src/tcas/ranking.py` เป๊ะ ๆ —
ถ้าแก้ฝั่งไหนต้องแก้อีกฝั่ง ไม่งั้นแอปกับ CLI จะตอบไม่ตรงกัน

**สมมติฐานของวิชาที่ยังไม่ได้สอบ** (`assessedScore`) — เติมวิชาที่ว่างด้วย % ที่
สมมติไว้แล้วคิดคะแนนใหม่ทั้งก้อน ต้องเติมกลับเป็น *คะแนนดิบ* ไม่ใช่บวก % เข้าไป
ตรง ๆ เพราะกลุ่มวิทยาศาสตร์เฉลี่ยจากสามวิชา ค่าตั้งต้นคือค่าเฉลี่ยของวิชาที่กรอก
ไปแล้ว (การเดาที่มีหลักฐานที่สุดเท่าที่มี) และผู้ใช้ปรับเองได้ — ปรับได้เมื่อไร
มันจึงกลายเป็นเครื่องมือถามว่า "ต้องทำได้เท่าไรถึงจะติดที่นี่"

**สามโหมดของคะแนนที่ใช้เทียบ** (`assessment()` คืน `{score, mode}`)

| mode | เมื่อไร | พาดหัวขึ้นว่า |
|---|---|---|
| `real` | กรอกครบทุกวิชา | "ด้วยคะแนน 67.93" |
| `partial` | กรอกบางวิชา เติมที่เหลือด้วย % ที่สมมติ | "ด้วยคะแนนที่ประเมินได้ 71.43" |
| `goal` | ยังไม่กรอกเลย แต่ตั้งคะแนนรวมเป้าหมายไว้ | "ถ้าทำได้ตามเป้า 70.00" |

โหมด `goal` ทำให้ใช้แอปได้ตั้งแต่ยังไม่สอบอะไรเลย — ใส่คะแนนรวมที่อยากได้
แล้วดูว่าคะแนนเท่านั้นเปิดประตูคณะไหนบ้าง พาดหัวต้องบอกที่มาเสมอ ไม่งั้น
"ผ่าน 39 คณะ" จากคะแนนที่ยังไม่ได้สอบ จะอ่านเหมือนเป็นผลจริง

**เก็บอะไรไว้ใน `S.settings` บ้าง** — `watch` (คณะที่ติดดาว) · `chanceFac`
(ชิปกรองคณะ, `[]` = ทุกคณะ) · `chanceUni` (สถาบัน) · `assumePct` (สมมติฐาน,
`null` = ใช้ค่าเฉลี่ยอัตโนมัติ) · `chanceOpen` (แถบไหนพับอยู่)
รายการที่ติดดาวขึ้นเป็นกลุ่มบนสุดและ**ไม่ขึ้นกับตัวกรอง** เพราะเป็นรายการที่
ตั้งใจเก็บไว้ดู ไม่ใช่ผลการค้นหา

⚠️ `targetProgram` ที่เป็น**สตริงว่าง** แปลว่า "ผู้ใช้เลือกยังไม่เลือกเอง"
ไม่ใช่ "ไม่มีค่า" — ถ้าใช้ `||` ธรรมดามันจะตกกลับไปใช้ `DATA.student.target_program`
ทันที ผลคือกด "— ยังไม่เลือก —" แล้วเด้งกลับคณะเดิมทุกครั้ง เหมือนปุ่มเสีย

## เส้นเป้าหมายรายวิชา (`targetLinePanel`)

คะแนนรวมเป็นตัวเลขที่เอาไปอ่านหนังสือไม่ได้ การ์ดนี้แปล "อยากได้ 70 คะแนน"
เป็น "TPAT1 210/300 · A-Level วิชาละ 70" พร้อม**ช่วงที่ยังเอาอยู่**

น้ำหนักทุกกลุ่มรวมกันได้ 100 พอดี ดังนั้น *ได้ p% ทุกวิชา = คะแนนรวม p*
เส้นเสมอกันจึงเท่ากับตัวเลขเป้าหมายตรง ๆ ไม่ต้องคำนวณอะไรเพิ่ม

**ช่วง = ขยับแล้วคะแนนรวมกระเพื่อมไม่เกิน 1 คะแนน** คือ `±(คะแนนเต็ม / น้ำหนักวิชา)`
เลือกนิยามนี้เพราะมันไม่ใช่ตัวเลขที่ตั้งขึ้นมาลอย ๆ และอ่านแล้วได้ข้อมูลจริง:

| วิชา | น้ำหนัก | เป้า (เมื่อเล็ง 70) | ช่วง |
|---|---|---|---|
| TPAT1 | 30.0 | 210/300 | 200–220 |
| คณิต 1 · อังกฤษ | 14.0 | 70/100 | 63–77 |
| ชีวะ · เคมี · ฟิสิกส์ | 9.3 | 70/100 | 59–81 |
| ไทย · สังคม | 7.0 | 70/100 | 56–84 |

อ่านแล้วรู้ทันทีว่า TPAT1 พลาดไม่ได้ ส่วนสังคมพลาดได้กว้างกว่าสองเท่า
**ทั้งช่อง "เป้า" และขอบล่างของช่วง clamp ไม่ต่ำกว่าเกณฑ์ขั้นต่ำ 30%** — เดิม
clamp แค่ขอบล่างของช่วง ลืมช่อง "เป้า" ซึ่งเป็นตัวเลขหลักที่คนอ่าน การ์ดจึงเคย
แนะนำ "เคมี 14/100" ให้คนที่ TPAT1 ได้เต็ม ทั้งที่นั่นคือการถูกคัดออกทันที
และขอบบนต้อง `Math.max(lo, …)` ไม่งั้นได้ช่วงกลับหัวอย่าง `"30–14"`
ส่วนหัวการ์ดต้อง clamp เส้นให้อยู่ใน 0–100 ก่อนแสดง ไม่งั้นเคยขึ้นว่า
*"ทำได้ -329% ในวิชาที่ยังเหลือ"* เมื่อทำวิชาที่กรอกแล้วได้ดีจนเกินเป้า

### สีของแถบต้องมาจาก `BANDS` ชุดเดียว

`BANDS[].tone` คือสะพานระหว่างสองการ์ด: การ์ดคะแนนใช้ `bandOf(...).tone` ตัวเดียว
กับที่รายการคณะใช้จัดกลุ่ม เดิมการ์ดคะแนนมีเกณฑ์ของตัวเอง (`0 / −5` และตอนกรอก
ไม่ครบใช้ `need ≤ 65 / ≤ 85` ซึ่งไม่ผูกกับคะแนนต่ำสุดของคณะไหนเลย) คณะเดียวกัน
จึงขึ้น **เขียวข้างบนกับเหลืองข้างล่างพร้อมกันบนจอเดียว**

### `group_percents()` หารด้วยจำนวนวิชา **ทั้งกลุ่ม** เสมอ — อย่าเขียนกลับ

วิชาที่ยังไม่กรอกต้องนับเป็น 0 ตามที่ทุกหน้าจอและ `report.py` เขียนไว้มาตลอด
เวอร์ชันเดิมเฉลี่ยเฉพาะวิชาที่กรอกแล้วคูณน้ำหนักเต็มของกลุ่ม = วิชาที่ยังไม่สอบ
ไป "ยืมคะแนน" จากวิชาที่สอบแล้ว ผลคือ **กรอกคะแนนเพิ่มแล้วคะแนนรวมลดลง**

| กรอก | เคยได้ | ที่ถูก |
|---|---|---|
| ชีวะ 80 | 22.40 | 7.47 |
| + ฟิสิกส์ 30 | 15.40 ⬇ | 10.27 |
| + เคมี 30 | 13.07 | 13.07 |

คะแนนที่พองนั้นถูกส่งต่อเข้า `rank` ไปเทียบคะแนนต่ำสุดของทุกคณะด้วย
กลุ่มเดียวที่มีหลายวิชาคือวิทยาศาสตร์ บั๊กนี้จึงโผล่เฉพาะตอนกรอกวิทย์ไม่ครบ

ผลพลอยได้: `have` ใน `required_percent()` เท่ากับคะแนนรวมที่โชว์บนจอพอดีแล้ว
ทั้งสองฝั่งจึงอ่านจาก `group_percents()` ตัวเดียวกัน ไม่มีสูตรซ้ำให้หลุดกันอีก

### บั๊กของ `requiredPercent` ที่แก้ไปแล้ว — อย่าเขียนกลับ

เวอร์ชันเดิมเอา `groupPercents()` (ซึ่งเฉลี่ย **เฉพาะวิชาที่กรอก**) มาเป็นคะแนน
กลุ่ม เท่ากับให้เครดิตน้ำหนักเต็มของกลุ่มไปแล้ว แต่ยังนับว่ากลุ่มนั้นว่างอยู่อีก
กรอกชีวะ 80 วิชาเดียวจึงถูกคิดเหมือนได้ 80 ทั้งกลุ่มวิทย์

> เคสจริง: TPAT1 250 + ชีวะ 80 เล็ง 70 คะแนน — ตอบว่า "ที่เหลือต้องได้ 37%"
> ทำตามนั้นแล้วได้จริง **54.9** ไม่ใช่ 70 · คำตอบที่ถูกคือ **62%**

สูตรที่ถูกคือหาร `n` (จำนวนวิชาทั้งหมดในกลุ่ม) ไม่ใช่จำนวนที่กรอก:

```
คะแนนกลุ่ม = (ผลรวม % ของวิชาที่กรอกแล้ว + m·x) / n
คะแนนรวม   = Σ w·S/(100n)  +  x · Σ w·m/(100n)
```

แก้แล้วทั้ง `scoring.required_percent()` และ `requiredPercent()` ในหน้าเว็บ —
ทดสอบด้วยการเติมคำตอบกลับเข้าไปแล้วคำนวณใหม่ ต้องได้เท่าเป้าพอดี

## ระบบดีไซน์ของหน้าเว็บ

แก้ทุกอย่างได้ที่ `web/tcas_app.html` ไฟล์เดียว (CSS อยู่บนสุด, JS อยู่ล่าง)

**ฟอนต์** — **IBM Plex Sans Thai** น้ำหนัก 400 กับ 600 ฝังอยู่ในไฟล์เป็น
base64 woff2 (18KB + 19KB) ไม่ได้โหลดจาก CDN แอปจึงใช้ได้แม้ออฟไลน์และ
ไม่มีทางตกไปฟอนต์อื่นเงียบ ๆ ที่ subset ไว้มี 227 ตัวอักษร คือภาษาไทย
ทั้งบล็อก + ละติน + เครื่องหมายที่แอปใช้จริง สัญลักษณ์คณิต/เคมี (Δ Σ ⇌ ₙ)
กับอิโมจิไม่ได้อยู่ใน subset จะตกไปฟอนต์ระบบตามปกติ

ถ้าจะเปลี่ยนฟอนต์ ต้อง subset ใหม่แล้วแปลงเป็น base64 ไม่ใช่แค่แก้ชื่อใน
`--sans` — ชื่อ `"Plex Thai"` ผูกกับ `@font-face` ที่ฝังไว้

*เดิมใช้ Sarabun ซึ่งเป็นฟอนต์ที่ ครม. กำหนดให้ใช้กับเอกสารราชการไทย
ปี 2553 หน้าตาแอปเลยอ่านเป็น "ใบงาน" ไม่ว่าจะทาสีอะไรลงไปก็ตาม*

**สี** — โทเคนอยู่ใน `:root` แล้วประกาศซ้ำอีกสองรอบ (`@media
prefers-color-scheme: dark` กับ `:root[data-theme=...]`) เพื่อให้ปุ่มสลับ
ธีมชนะค่าของระบบได้ทั้งสองทิศ พื้นเป็น**เทาอุ่น** สีหมึกเป็น**ม่วงเข้ม**
(`--ink`, ใช้กับแถบบน จอจับเวลา และไอคอนแอปใน `icons.py` — เปลี่ยนแล้ว
ต้องเปลี่ยน `THEME_COLOR` ใน `webexport.py` ตามด้วย)

### สีวิชามีสามเฉด — เลือกให้ถูกตัว

แต่ละวิชาใน `[data-s="..."]` ประกาศสามค่า **ใช้ผิดตัวคือคอนทราสต์ตก**

| โทเคน | ใช้กับ | เกณฑ์ที่ตั้งไว้ |
|---|---|---|
| `--sc` | พื้นอ่อน เส้นขอบ เม็ดสีนำหน้า | ไม่ได้ตั้งเกณฑ์ (ไม่ใช่ตัวหนังสือ) |
| `--scd` | **พื้นแถบสีเข้มที่มีตัวหนังสือขาว** (`.dayband`, `.scoreband`) | ขาวบนพื้น ≥ 5.0:1 |
| `--sct` | **ตัวหนังสือสีวิชา** บนพื้นการ์ด (เช่น `--tc` ของไทล์) | ≥ 4.5:1 ทั้งสองธีม |

`--sct` สลับเฉดตามธีมให้เอง (สว่าง→`--scd`, มืด→`--sc`) เพราะพื้นหลังกลับด้าน
กัน ถ้าฮาร์ดโค้ดตัวใดตัวหนึ่งจะมีธีมหนึ่งได้แค่ ~2.8:1 เสมอ

**ห้ามเอา `--sc` ไปทาตัวอักษร** — เขียวมะกอกกับเทอร์ควอยซ์ตัดกับพื้นไม่ถึง
4.5:1 ใช้ `--sct` แทน

`--scd` คำนวณจากสีเดิมโดยลด lightness ใน OKLCh (คงเนื้อสี) จนถึงเกณฑ์
**และคิดรวมลายจุดขาว 5% ที่ทับอยู่บนแถบด้วย** — ลายจุดนั้นกินคอนทราสต์ไปราว
0.6 ถ้าลืมนับ ตัวเลขบนกระดาษจะผ่านแต่ของจริงตก
สคริปต์ที่ใช้คำนวณอยู่ในบันทึกงาน (`deep2.mjs`) เกณฑ์ที่ตั้ง = 4.62 เผื่อไว้

*วัดของจริงแล้ว: จุดที่สว่างที่สุดของแถบทั้ง 11 แบบ × 2 ธีม อยู่ที่ 4.68–5.54:1*

**มุมโค้ง** — `--r` 14px (การ์ด) · `--r-sm` 10px (ปุ่ม ช่องกรอก) ·
`--r-xs` 6px · `--pill` 99px (ชิป)

**ลูกเล่น** — ทุกอันเช็ค `prefers-reduced-motion` ก่อนเสมอ
- `runCounters()` — ตัวเลขวิ่งขึ้น จำค่าเดิมด้วย `data-key` เพื่อไม่ให้
  เด้งกลับศูนย์ทุกครั้งที่ render ใหม่
- `ringHTML()` — วงแหวนวาดตัวเองด้วย `stroke-dashoffset`
  (โหมดลดการเคลื่อนไหวจะกระโดดไป `--dash-to` ทันที ไม่ใช่ค้างว่าง)
- `confetti()` — เรียกจากที่เดียวคือตอนปิดงานครบทั้งวัน **ห้ามเรียกตอน
  ติ๊กทีละบล็อก** ไม่งั้นจะกลายเป็นเสียงรบกวนจนตอนที่ควรดีใจจริงไม่เหลือค่า
- `.blk.done.just` — เครื่องหมายถูกถูกวาดเฉพาะแถวที่เพิ่งกด
- `go()` — สลับแท็บผ่าน View Transitions ถ้าเบราว์เซอร์รองรับ

### ขนาดตัวอักษรเป็น `rem` ทั้งไฟล์ — อย่าเขียน `px` กลับเข้าไป

`font-size` ทุกจุด (99 แห่ง) เป็น `rem` เพื่อให้ค่าที่ผู้ใช้ตั้งไว้ในเบราว์เซอร์
มีผลจริง `px` เป็นหน่วยตายตัวและ**ไม่ขยับตามการตั้งค่านั้นเลย** ขนาดอื่น
(padding, ความกว้าง) ยังเป็น `px` ได้ตามเดิม

ของที่ต้องคิดเผื่อไปด้วยเมื่อตัวอักษรใหญ่ขึ้น
- `--tabh` — ความสูงจริงของแถบแท็บ วัดใน `syncStickyOffset()` แล้วเอาไปเป็น
  `padding-bottom` ของ `body` เดิมฮาร์ดโค้ด 78px ซึ่งกินเนื้อหาบรรทัดสุดท้าย
- `body { overflow-wrap: break-word }` — คำที่ตัดไม่ได้ (ชื่อไฟล์ ลิงก์)
  ดันหน้าให้เลื่อนซ้ายขวา
- `.sgrid` ใช้ `minmax(0, 1fr)` ไม่ใช่ `1fr` และเหลือคอลัมน์เดียวใต้ 360px

ทดสอบแล้วที่ root font 32px (200%) × 6 หน้า — ไม่มีสกรอลล์แนวนอน

### ขนาดพื้นที่กดขั้นต่ำ 40px

ปุ่มและช่องกรอกทุกตัวสูงอย่างน้อย 40px (`.btn-sm`, `.fchip`, `.hours-in`,
`input`, `select.sel`) ส่วนไอคอนเล็กที่ขยายไม่ได้เพราะจะทำให้แถวสูงผิดสัดส่วน
(`.prow-star` 26px, `.blk-res` 30px) ใช้ `::before` แบบ `position:absolute`
ขนาด 44×44 ยืดเฉพาะพื้นที่กด **ไม่ยืดของที่มองเห็น**

```css
.prow-star::before{content:"";position:absolute;left:50%;top:50%;
  width:44px;height:44px;transform:translate(-50%,-50%)}
```

แถวที่มีไอคอนแบบนี้ต้อง `min-height: 44px` ด้วย ไม่งั้นพื้นที่กดของสองแถว
ที่ติดกันจะซ้อนทับกัน

**กับดักที่เคยเจอมาแล้ว**
- อย่าใส่ `overflow: hidden` บน `.card` — มันทำให้การ์ดกลายเป็น scroll
  container แล้วหัวสัปดาห์ที่เป็น `position: sticky` จะไปทับแถวของตัวเอง
- อะไรที่เป็น `<button>` แล้วตั้ง `border-top`/`border-bottom` อย่างเดียว
  ต้อง `border: 0` ก่อน ไม่งั้นเหลือ `2px outset` สีดำของเบราว์เซอร์สองข้าง
- อย่าผสม `ui-monospace` กับข้อความไทย — ตัวเลขกับตัวหนังสือจะกลายเป็น
  คนละฟอนต์ในบรรทัดเดียว ใช้ `font-variant-numeric: tabular-nums` แทน
