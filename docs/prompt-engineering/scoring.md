# ระบบให้คะแนน & แบบประเมินตนเอง

ใช้ไฟล์นี้คู่กับ `exercises.md` — ให้คะแนนทุก prompt ที่เขียน เพื่อเปลี่ยนการฝึก
จาก "รู้สึกว่าดีขึ้น" เป็น "วัดได้ว่าดีขึ้น"

---

## A) Rubric หลัก — ให้คะแนน prompt 1 อัน (เต็ม 24)

ให้คะแนนแต่ละมิติ 0–3 (0 = ไม่มี, 1 = มีแต่อ่อน, 2 = ดี, 3 = ดีเยี่ยม/ครบ)

| # | มิติ | 0 | 1 | 2 | 3 |
|---|------|---|---|---|---|
| 1 | **เป้าหมาย/งานชัด** | ไม่รู้ว่าจะเอาอะไร | คลุมเครือ | ชัดพอใช้ | งานเดียว ชัดเป๊ะ วัดผลได้ |
| 2 | **บริบท & เหตุผล** | ไม่มี | มีนิดหน่อย | บอกว่าใคร/ทำไม | บริบทพอดี high-signal |
| 3 | **ความเฉพาะเจาะจง/ข้อจำกัด** | ลอย ๆ | กว้าง | มีข้อจำกัดบ้าง | ระบุชัด (ตัวเลข/ขอบเขต/ห้าม) |
| 4 | **ตัวอย่าง (few-shot)** | ไม่มีเมื่อควรมี | 1 ตัวอย่างอ่อน | ตัวอย่างตรงงาน | หลากหลาย ครอบคลุม edge |
| 5 | **โครงสร้างการให้เหตุผล** | สั่งตอบเลยทั้งที่ซับซ้อน | พูดถึงลอย ๆ | มี CoT/ขั้นตอน | คิดก่อนตอบ + แยกส่วนชัด |
| 6 | **รูปแบบผลลัพธ์** | ไม่กำหนด | บอกหลวม ๆ | กำหนดฟอร์แมต | schema เป๊ะ parse ได้ |
| 7 | **การวัดผล/วนปรับ** | ไม่คิดถึง | บอกว่าจะดูเอง | มีเกณฑ์ตัดสิน | มี eval set + เทียบเวอร์ชัน |
| 8 | **ความปลอดภัย** | เปิดช่อง injection | รู้ตัวแต่ไม่กัน | แยกคำสั่ง/ข้อมูล | instruction hierarchy + ทดสอบโจมตี |

**เกณฑ์เกรด:** 21–24 = เชี่ยวชาญ · 17–20 = เก่ง · 12–16 = กลาง · < 12 = ต้องปรับ

> หมายเหตุ: บางมิติไม่เกี่ยวกับโจทย์ง่าย ๆ (เช่นมิติ 8 ในงาน L1) — ตอนให้คะแนน
> ระดับต้น ๆ ใช้เฉพาะมิติที่เกี่ยว แล้วคิดเป็น % ของคะแนนเต็มที่ใช้จริง

## B) เกณฑ์ผ่านแต่ละระดับ

| Level | มิติที่เน้นวัด | ผ่านเมื่อ |
|-------|----------------|-----------|
| L1 | 1, 2, 3, 6 | ได้ ≥ 80% ของมิติที่เน้น 2 ครั้งติด |
| L2 | 3, 4, 6 | few-shot ทำให้ output ตรงฟอร์แมตทุกครั้งในเคสทดสอบ |
| L3 | 1, 5 | คุณภาพคำตอบดีขึ้นชัดเมื่อเพิ่ม reasoning (มีหลักฐานเทียบ) |
| L4 | 5, 7 | chain/ReAct รันต่อกันได้, self-consistency ลด error วัดได้ |
| L5 | 2, 7, 8 | มี eval set จริง + ตัดสิน A/B ด้วยตัวเลข + กัน injection ผ่านเคสโจมตี |
| L6 | ทุกมิติ | system prompt + agent ใช้งานจริงได้ + เห็นคะแนน eval ดีขึ้นเป็นรอบ |

## C) แบบประเมินตนเองก่อนเริ่ม (ทำครั้งแรก)

ตอบ "ทำได้คล่อง / ทำได้บ้าง / ยังทำไม่ได้" แต่ละข้อ แล้วดูว่าหยุดคล่องที่ระดับไหน:

- [ ] เขียน prompt แบบ RTCF ได้โดยไม่ต้องนึกนาน (L1)
- [ ] บังคับ output เป็น JSON/ตารางที่ parse ได้ทุกครั้ง (L2)
- [ ] ใช้ few-shot คุมสไตล์/คลาสได้ (L2)
- [ ] ใช้ CoT แล้วรู้ว่าเมื่อไรควร/ไม่ควรใช้ (L3)
- [ ] ออกแบบ prompt chain หลายขั้นได้ (L4)
- [ ] เขียน prompt แบบ ReAct ให้ใช้ tool ได้ (L4)
- [ ] สร้าง eval set + วัด A/B ด้วยตัวเลข (L5)
- [ ] กัน prompt injection เป็น (L5)
- [ ] เขียน system prompt ระดับโปรดักชันได้ (L6)

**ระดับปัจจุบันของคุณ (ประเมินเริ่มต้นโดยผม): L2 ปลาย / ต้น L3** — ดูเหตุผลใน
`README.md` หัวข้อ "ประเมินระดับปัจจุบัน" จุดที่ควรโฟกัสก่อนคือ **มิติ 4 (ตัวอย่าง),
6 (ฟอร์แมต), 7 (วัดผล)**

## E) เกณฑ์ "เก่งกาจ" (เป้าหมายปลายทางของคอร์ส)

ถือว่าบรรลุเป้าเมื่อทำได้ครบ:
1. ผ่าน L1–L6 ทุกระดับด้วย rubric ≥ 80%
2. มี **eval set ส่วนตัว** อย่างน้อย 1 ชุดที่ใช้วัด prompt จริงในงานของตัวเอง
3. ปรับ prompt 1 งานจริงจน metric ดีขึ้น **วัดเป็นตัวเลขได้** (ไม่ใช่ vibe)
4. เขียน system prompt + กัน prompt injection ผ่านการทดสอบโจมตีได้
5. **สอน/อธิบาย** ให้คนอื่นเข้าใจได้ว่าทำไม prompt หนึ่งดีกว่าอีกอัน — เกณฑ์
   สุดท้ายของความเชี่ยวชาญคือถ่ายทอดได้
